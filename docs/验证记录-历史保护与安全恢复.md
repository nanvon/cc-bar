## 2. 存储与恢复规则

生产位置为 `~/Library/Application Support/CCBar/usage-history/`：

| 文件 | 用途 |
|---|---|
| `current.json` | 当前完整提交：日 / 对话 / 周期 / 进度 / DSH，envelope v1 |
| `previous.json` | 轮转前验证有效的 current 原始字节，独立完整提交 |
| `established` | 开始使用新存储的标记，防止两份快照丢失后重新迁移过期缓存 |
| `quarantine/` | previous 有效时隔离的损坏 current；全部不可用时原文件原地保留 |

内层支持基线格式：ScanState v15、日 v10、对话 v8、周期 v4、DSH v2；旧 DSH v1 按既有 pending 语义迁移。内外层版本分别检查；未知版本不得当成首装或普通损坏后继续写。

提交顺序：结构校验 → 编码 → 有效 current 原样轮转 previous → 首次保存 established 标记 → 原子替换 current → 发布内存。切换前失败保留旧提交；切换后返回错误时，服务回读提交 ID 与时间确认新提交已经落盘，避免内存错误回退。标记写入后首次 current 写失败、且重启时没有有效快照，会保守停止；不会偷偷重新迁移。此协议覆盖异常与进程中断，不承诺断电耐久性。

加载优先 current，再 previous；current 有效时不额外解码 previous。两份都不可用且存在新存储证据时停止采集和写入，不回读旧缓存。无新存储证据时才尝试旧格式迁移；旧文件损坏或不兼容同样不会当成首次安装。迁移保存失败显示错误，下一轮普通扫描立即重试保存，不等待节流窗口或新增用量。

对话缺失 / 损坏 / 错代或进度不可信时，只展示可用历史，使用不可续扫的占位进度并进入核对。核对比较完整用量向量，不接受相加、逐桶最大值或总量不减少。核对失败后明确暂停本地采集；日志变多、缺失时重复重算仍可能失败，只有恢复日志或解除临时读写故障后才可能恢复。

## 7. 2026-10-08 手动重算规则调整
