# cc-bar 产品需求

> 描述当前已交付版本的功能范围与边界。新需求迭代时以本文为准；与代码不一致以代码为准并同步回这里。

---

## 0. 产品定位

- **形态**：常驻菜单栏的小工具（Accessory App，默认不占 Dock；打开主窗口期间临时显示 Dock 图标，关闭后恢复）。
- **平台**：macOS 14 Sonoma+（依赖 SwiftUI `MenuBarExtra(.window)`、`@Observable`、`SMAppService`）。
- **设计**：以 macOS HIG 为底座，关键信息层（百分比、进度、KPI、HUD）按设计稿落地自绘组件；非关键层（Picker / Toggle / DatePicker / TabView / Material）全部用系统默认。
- **两类数据**：订阅额度（剩余比例、重置时间）来自服务端，按订阅和账号组织，用于菜单栏、悬浮窗、Popover 与额度页；本机用量来自会话日志，按 Agent 统计，用于概览、对话、项目页。Popover 花费与额度页周期用量是用对应 Agent 的本机用量近似订阅消耗：默认只计该 Agent 自己日志里的订阅模型（Claude 只计 `claude-*`；Codex 只计 OpenAI 自家模型，可带 `openai/` 或 `openai-codex/` 前缀；按模型名近似判断，第三方渠道转发的同名模型和 API Key 调用分不出来，仍算订阅），Codex 可打开「包含其他 Agent 中的 Codex 订阅用量」再计入 Pi / OpenCode / DSH 里的 Codex 订阅用量；Cursor 花费取远端计量。新增展示位时按这条划分口径。
- **一句话价值**：装上它 → 不打开 CLI 也能随时看到 Codex / Claude Code / Antigravity 的当前额度，以及启用后的 Cursor Total / Auto / API 额度，并查看 Codex / Claude Code / Antigravity / Pi / OpenCode / DSH 的本地 Token 与费用；启用 Cursor 统计后，还可查看该 Cursor 账号全设备的服务端计量用量。

## 1. 账号自动识别

- 启动时扫描本机已有的 Codex / Claude Code / Antigravity / Cursor / Command Code / OpenCode Go 凭据：
  - Codex：`~/.codex/auth.json`。支持两种凭据形态：① OAuth 模式（`tokens.*`，解析 JWT 拿邮箱 / plan / accountId，到期自动续期）；② personal access token 模式（顶层 `personal_access_token`，即 ChatGPT Team/Enterprise 后台创建的 Codex 访问令牌，不透明、不续期，身份由 `wham/usage` 响应回填）。导入「其他 Codex 账号」时也接受这两种形态的粘贴。
  - Claude：先读 `~/.claude/.credentials.json`；不存在则读 macOS Keychain 通用密码项 `Claude Code-credentials`（service name）。邮箱兜底从 `~/.claude.json` 顶层 `oauthAccount.emailAddress` 读取。
  - Cursor：只读 `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` 的 `cursorAuth/accessToken`，解析 JWT 仅用于识别账号；不读取 refresh token、不调用 OAuth、不写 Cursor SQLite 或 cc-bar Keychain。Cursor 开启登录加密后（值为 `cursor-safe-storage:v1:` 开头），经系统 `security` 工具读钥匙串 `Cursor Safe Storage` 的密码解密，密钥只缓存在内存里；明文 JWT 照旧直接使用。
  - Antigravity：优先识别桌面端 / 新版 agy 共用的钥匙串登录（服务 `gemini`、账户 `antigravity`）；仅安装并登录 GUI 即可使用，不要求 agy。钥匙串缺失时兼容旧 jetski / CLI token / oauth_creds 文件；条目存在但读不出时提示读取失败，不借用旧账号。无 agy 时使用 GUI 登录直查云端额度，自动续期结果存 CCBar 自己的钥匙串并绑定原始登录，不修改桌面端登录。已有 agy 时保留原 CLI 优先路径。
  - Command Code：5 级只读自动扫描，按 `~/.commandcode/auth.json` → `~/.pi/agent/auth.json` → `~/.local/share/opencode/auth.json` → 环境变量 `COMMAND_CODE_API_KEY` / `COMMANDCODE_API_KEY` → macOS Keychain 手动 Key 的顺序取第一个命中的；也可在设置中把凭据来源切成「手动 API Key」，此时只读 Keychain。
  - OpenCode Go：只读自动扫描，按 OpenCode 的 `auth.json`（`$XDG_DATA_HOME/opencode/`，默认 `~/.local/share/opencode/`）→ `~/.pi/agent/auth.json` 中的 `opencode-go` 项 → 环境变量 `OPENCODE_API_KEY` → macOS Keychain 手动 Key 的顺序取第一个命中的；也可切成「手动 API Key」，此时只读 Keychain。不写 OpenCode / Pi 的任何文件。
- 不做 App 内登录流程。前提：用户已经在终端跑过 `codex login` / `claude` 登录。
- 用户可在「设置 → 服务与账号」开启或关闭每个服务，一个服务一个开关，同时管额度和用量；Codex、Claude Code 默认开启；Antigravity 在新安装首次启动时检测到凭据才默认开启，未检测到则关闭（已装机用户保留原设置）；Cursor、Command Code 与 OpenCode Go 的 Provider 开关默认关闭，启用后才查询远端接口。Antigravity 的开关同时管额度和本机用量：用量读取 `~/.gemini/antigravity`、`antigravity-cli`、`antigravity-ide`、`antigravity-backup`、`antigravity-acp` 与 `~/.config/antigravity` 下的 `conversations/*.db`（App、IDE、agy CLI 同一种 SQLite 对话库，合并为一个服务统计），在本机计算 Token 与估算费用；App 记录只写占位编号或通用名时，模型名按编号表推断。Command Code 与 OpenCode Go 作为订阅额度 Provider，进入「设置 → 服务与账号」、Popover、菜单栏与桌面悬浮窗；不进入主窗口用量统计。使用 OpenCode Go 模型的对话照常计入 OpenCode / Pi 的本机用量。
- 首次启动若不存在 `~/.claude/.credentials.json`，且尚未提示过，会先弹一次说明性 Alert（"接下来 macOS 会弹 Keychain 授权窗口，请选择始终允许"），再触发系统 Keychain 弹窗。
- 第一次需要读取 Claude 桌面版登录（钥匙串 `Claude Safe Storage`）时，先弹说明框「允许读取 Claude 桌面版登录」（继续 / 暂不），选「继续」后系统询问「security」能否访问，选「始终允许」后更新 CCBar 不再询问。选「暂不」或在系统框拒绝后不再自动询问，可在「设置 → 服务与账号」的 Claude Code 行点「授权…」重新授权。
- Cursor 登录加密后同样处理：Cursor 开启（或已走过授权说明）且第一次需要读取钥匙串 `Cursor Safe Storage` 时，先弹「允许读取 Cursor 登录」（继续 / 暂不），选「继续」后系统询问「security」能否访问，选「始终允许」后更新 CCBar 不再询问。未授权时弹出面板显示「未授权读取 Cursor 登录，请到「设置 → 服务与账号」授权」，设置的 Cursor 行显示「未授权读取 Cursor 登录」与「授权…」。Cursor 未开启且没走过授权说明时只做检测，不读钥匙串。

## 2. 菜单栏标签

- 标签是模板图像（template NSImage），自适应深浅菜单栏。
- 默认顺序：**Codex → Claude Code → Antigravity → Cursor → Command Code → OpenCode Go**；用户可在「设置 → 服务与账号」拖拽调整，与 Popover / 悬浮窗 / 主窗口共用同一顺序。
- 每段为 `<服务 logo>  <百分比>`：
  - Logo 用项目内置的 `codex.svg` / `claude.svg` / `antigravity.svg` / `cursor.svg` / `commandcode.svg` / `opencode.svg`（OpenCode Go 复用 OpenCode 图标；菜单栏会做模板化变灰）。
  - 百分比用 `monospacedDigit`。
- 设置项：
  - 显示哪个服务（Codex / Claude Code / Antigravity / Cursor / Command Code / OpenCode Go，可分别开关）。Cursor 始终只显示 Total；Auto / API 详见 Popover，不能被伪装为周额度。Command Code 与 OpenCode Go 支持 5 小时与周额度。
  - 显示哪个额度窗口：主要额度 / 周窗口 / 两者。主要额度通常是 5 小时；服务端临时只返回周额度时自动显示周额度。两者相同时只显示一次。
- 都关闭时仍保留一个占位 logo，避免菜单栏完全消失。

## 3. Popover 总览

- 点击菜单栏图标弹出宽 340pt 的窗口。
- 顺序：跟「设置 → 服务与账号」里的 Provider 自定义顺序（默认 Codex → Claude Code → Antigravity → Cursor → Command Code → OpenCode Go）；每个服务一个 block，仅显示已启用项，用 Divider 分隔。Codex 下的其他导入账号仍紧跟 Codex 主 block。
- Header 一行：标题「Usage / 用量」+ 副标题（最近一次刷新相对时间 / 刷新失败 / 等待数据）+ 状态点（live / stale / offline）+ 四个一级图标按钮（刷新 / 统计 / 设置 / 退出），没有 kebab 菜单也没有 footer。
- 每个 block 字段：
  - 服务 tile + 服务名 + 副标题（Provider · Plan）。
  - 主要额度：32pt 剩余百分比 + 16pt `%` + 动态窗口标签 + 进度条 + 重置倒计时；各 Provider 复用既有「今日 cost」+「本周 cost」展示位。
  - 次要额度：存在且与主要额度不重复时显示缩小版进度条；Claude 继续展示 Fable 等模型专项周额度。
  - Cursor：主额度为 Total，次要条展示 Auto 与 API；今日 / 本期费用汇总已成功拉取的远端计量数据，位置和样式与 Codex / Claude 一致；本期指当前计费周期（与 Total 重置时间同一周期，从周期开始那天算起），拿不到周期时回退为本周；有覆盖或字段缺口时保留当前金额并在后台补拉，完全没有远端快照时才显示既有占位。Unlimited 以 `∞` + `UNLIMITED` 标签表示,不渲染伪造百分比或进度条。
  - Antigravity：有独立 Argon 桶时共五行：主条 `GEMINI 4 ARGON`（周额度），下面依次为 `GEMINI 5H`、`GEMINI WK`、`CLAUDE 5H`、`CLAUDE WK`。菜单栏和悬浮窗的主要额度跟随 Argon；无独立 Argon 桶时保留原四行，缺失或禁用的桶不显示、不推算。Argon 不与普通 Gemini 周额度合并；查询失败保留已有快照。
  - Command Code：主额度为 5 小时窗口，次要条展示周窗口，两者的 cap 与已用量都由服务端 `windowLimits` 返回，不在本地写死；GOAT 套餐额外有一条月度额度（按月总额 70 换算剩余比例，重置时间取订阅的 `currentPeriodEnd`）。不展示用量费用。
  - OpenCode Go：主额度为 5 小时窗口，次要条为周窗口，另有一条月额度，三者的已用比例和重置时间都由服务端返回；已用完（`rate-limited`）的窗口显示 0% 剩余。副标题显示「OpenCode」（没有可读的账号信息）。不展示费用和服务状态点。403 且服务端说明该 key 没有 Go 订阅时，提示「该 API Key 没有 OpenCode Go 订阅」。
  - 失败时沿用 block 下方既有短提示；Cursor 与 Command Code 仅显示通用失败状态，不直出远端技术错误原文。
- 关闭全部服务时显示"未启用任何服务 / 到「设置 → 账号」开启"占位。
- 最近对话：服务 block 之后列出今天有活动的本机对话，按最近活动倒序，默认最多 5 条（设置里可选 3～10 条），每条显示服务、对话标题、输出速度(每行唯一突出的数字)、Tokens、估算费用和缓存命中率（按对话全部时间汇总，与对话详情一致）；今天没有对话时整块不显示。点击打开统计页对话视图并选中该对话。Cursor 没有本机会话，不出现。可在「设置 → 外观与显示 → 弹出面板 → 最近对话」关闭（默认开），同一行调整条数。
- 状态点阈值：以当前额度刷新间隔为基准，age ≤ 1.5× 间隔为 live，≤ 3× 为 stale，超过为 offline。

## 4. 桌面悬浮窗（Floating HUD）

- 设置里可勾选「显示悬浮窗」。
- 按「设置 → 服务与账号」的 Provider 自定义顺序，逐行展示已启用服务的主要额度（18pt tile + 进度条 + 大字百分比）。Cursor Unlimited 只显示 `∞`，不显示 100%。
- 行可分别开关，结果只显示一行 / 全部隐藏。
- 样式：14pt 圆角 + `.popover` material + 0.5pt hairline 描边；无标题栏；不抢焦点；可拖动；始终置顶。
- 位置记忆：拖动后写回 UserDefaults；屏幕外重启时回落到默认右上角。
- 拖到距屏幕边缘 20pt 以内自动吸附到该边。

## 5. 自动后台刷新

- 后台三件周期任务共用**单一时基**（不是各起一条循环）：
  - 额度 API 刷新：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
  - 本地日志扫描：默认 5 分钟，可选「1m / 2m / 3m / 5m / 10m」；启动后仍立即增量扫描一次，手动刷新不受周期限制。已有用户已保存的间隔保持不变。
  - 服务状态：固定 5 分钟，不跟随上面两个设置。
- 调度器每次只睡到最近一个到期任务，醒来时把 5 秒容差内到期的任务一并执行，减少唤醒次数；系统睡眠期间停表、唤醒后立即补跑一轮；屏幕休眠或锁屏期间所有间隔 ×4 降频，恢复可见时立即补一次全量刷新。
- 端点：
  - Codex：`GET https://chatgpt.com/backend-api/wham/usage`，带 `ChatGPT-Account-Id` 头。
  - Claude：`GET https://api.anthropic.com/api/oauth/usage`
  - Antigravity：优先 `agy -p "/quota" --output-format json --log-file /dev/null`，单次关闭 agy 自动更新、不发起模型回合。agy 的 access_token 过期时，cc-bar 先用它的 refresh_token 向 Google 试续期一次（新 token 丢弃，不写任何文件）：能续期就照常调用 agy；Google 明确拒绝（`invalid_grant`）或凭据文件和钥匙串里都没有 agy 凭据时视为登录失效，不调用 agy，直到 agy 凭据变化（用户重新登录）。钥匙串读取被拒绝时按普通失败处理，不判为登录失效。登录失效时，已有 CLI / Argon 快照则保留快照并提示「请在 Antigravity 中重新登录,然后刷新」，没有该快照则照常走云端；cc-bar 不替用户打开登录页。周期刷新最短 120 秒，CLI 失败冷却 10 分钟；已有 CLI / Argon 快照时失败不以另一额度池覆盖。无可用 CLI 结果且没有该快照时，使用原 daily 域 Cloud Code 查询，主域作失败回退；套餐优先读取 `paidTier`，免费层（`free-tier`）显示 `Free`；重置时间只使用服务端值。agy 取数成功后用 agy 自己的登录补查套餐，每 6 小时重查一次，会员等级变化最晚 6 小时内在 Popover 更新。额度时间线仍记录共享 Gemini 的 5 小时 / 周额度，不混入 Argon 独立周池。
  - Cursor：`GET https://cursor.com/api/usage-summary`，只携带 Cursor.app 只读登录态构造的 Cookie；401 时最多重读一次本地 SQLite，绝不 OAuth 刷新。
- 限流策略：
  - 同一服务两次成功之间至少 60 秒，周期性触发若间隔不足直接跳过。
  - 收到 429 后该服务进入固定 10 分钟退避（不是指数退避），期间所有请求短路。
  - 手动「立即刷新」可绕过 60s 节流但仍遵守 429 退避。
- 手动刷新会在两种情况下触发一次 Claude CLI 兜底（启动 `claude` 进程，向其 stdin 写入 `/usage`，解析输出）：Claude API 失败且**完全没有可展示缓存**，或 Claude 凭据已过期。CLI 兜底有独立 10 分钟冷却。
- Token 续期：
  - **Codex** 在 access_token 距离过期 5 分钟内用 refresh_token 自动续期，并把新 token 写回原存储位置（`auth.json` 或 cc-bar 自己的 Keychain 条目）。发请求前会重读一次存储，若 `codex` CLI 已自行轮换过就直接采用，不拿陈腐 token 去撞服务端的重用检测。
  - **Antigravity 自动续期**：临期 5 分钟通过 Google OAuth 续期，无需运行桌面端或 agy。GUI / 旧 CLI 的原始凭据只读，续期结果存 CCBar 自己的钥匙串；jetski / oauth_creds 继续写回各自文件。切号 / 退出不复用旧账号缓存，401 最多续期重试一次，429 遵守原有退避。
  - **Claude 不续期**。Anthropic 的 refresh_token 一次性、刷新即轮换，cc-bar 一旦刷新就会把 Claude Code CLI / Desktop 挤下线，因此只读采用它们刷新后的结果。凭据过期时保留上一次额度快照并提示「登录已过期，请在终端运行一次 claude」；若改用 Claude 桌面版登录只差钥匙串授权（用户拒绝过），提示「登录已过期，请到「设置 → 服务与账号」授权读取 Claude 桌面版」，本地 Token / 费用统计不受影响。
- 网络代理（「设置 → 数据与刷新 → 网络代理」），对 cc-bar 的全部请求生效，不按服务分别设置：
  - 跟随系统（默认）：读 macOS 系统代理，与此前行为一致。
  - 手动：HTTP 或 SOCKS5，填写主机和端口，不支持认证。
  - 手动模式下代理不可用（未填、填错、连不上）时停止取数并报错，不改为直连或系统代理，避免带着账号凭据的请求从另一个出口发出。`claude`、`agy` 子进程注入同一个 HTTP 代理；SOCKS5 下不调用这两个命令行（Claude Code 不支持 SOCKS 代理），Antigravity 改走云端接口。Sparkle 应用更新始终跟随系统代理。
- 启动行为：先读本地额度缓存让 UI 立刻有数；启动 7 秒后触发一次额度刷新，之后按调度器节奏轮询；网络或本地服务失败保留已有快照，仅以小字提示。

## 6. 本地用量统计

- 数据源：纯本地 JSONL，**额度 API 不返回历史数据**。
  - Claude：`~/.claude/projects/**/*.jsonl`，解析 `type=assistant` 行；`message.usage.speed` 的 `standard` / `fast` 原样映射，缺失或未来新值记为未识别。同一 `message.id` 跨文件全局去重（sidechain / subagent 会重复引用同一条），按对话记录已计入的 ID，没有条数上限。缓存写入原始 Tokens 继续使用 `cache_creation_input_tokens` 合计；计价时读取 `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`，分别按当前 Standard / Fast 基础输入价的 1.25× / 2× 计算。
  - Codex：`~/.codex/sessions/**/*.jsonl` + `~/.codex/archived_sessions/**/*.jsonl`，以及 Codex 压缩冷会话后生成的同名 `.jsonl.zst`（只读解压，不改动文件），按 `turn_context` 提供的当前 model 给随后的 `event_msg/token_count` 打标签；`thread_settings_applied.thread_settings.service_tier` 的 `priority` / `fast` / `default` 分别映射为 Fast / Fast / Standard，并跨增量扫描保存当前档位。token 用 `payload.info.last_token_usage`，billable input = `input_tokens − cached_input_tokens − cache_write_tokens`。`cache_write_tokens` 兼容顶层及 token details；当前本地日志未提供时按 0，不推测。相同 `total_token_usage` 签名的重复 `token_count` 不再次入账。
  - Pi：`~/.pi/agent/sessions/**/*.jsonl`，解析 `type=message` 的 assistant 行；`message.usage` 直接提供 input / output / cacheRead / cacheWrite / totalTokens。`message.cost.total > 0` 时优先采用日志总价及有效分项；分项与总价只有 JSON 浮点尾差时保留分项并对齐总价。价格缺失或为 0 且有 Token 时，复用统一 Pricing 的在线目录 → 本地价格表补算。compaction / branch_summary 带 `usage` 时一并计入（对齐 pi `/session` 合计口径）。跨文件按 entry id + ISO 时间戳全局去重（fork / clone 复制旧行），同 Claude 按对话记录已计入的 ID。模型标签为 `provider/model`，速度档位恒为 Standard。
  - OpenCode：`~/.local/share/opencode/opencode.db`（SQLite，Desktop / CLI 共用，只读）。兼容 v1 `session/message` 和 v2 `session_v2/session_message`；迁移共存时相同消息 ID 优先采用 v2，保留 v1 独有历史，避免重复计费；旧版 OpenCode 只有 `session_message`、没有 `session_v2` 时只读 v1 表。只计已完成 assistant 的 `cost`（USD）和 `tokens{input, output, reasoning, cache{read, write}}`，reasoning 并入 output；有效 `cost > 0` 优先采用日志总价，分项按价格表占比缩放；价格缺失或为 0 且有 Token 时由在线目录 → 本地价格表补算，未知价格按 `$0` 展示。两版角色 / 模型字段分别解析，模型标签统一为 `providerID/modelID`。会话标题 / 项目来自对应 session 表；分支字段不存在时留空，空标题用 user 文本 / text part 兜底。按会话变动签名重读并替换贡献，消息跨轮完成或用量更新不会漏算或重复累加；读取失败保留旧统计并提示错误。升级旧缓存时只重建现存 OpenCode 会话，不触发其他服务全量重扫。
  - DSH：`~/.dsh/sessions/<项目段>/<会话段>/session[.vN].jsonl[.zstd]`，只读**默认根**（不做 Desktop 自定义数据目录、显式 `DSH_HOME`、Beta home 的自动发现；没有默认日志不能据此断定用户未安装 DSH）。日志是**多帧拼接的 zstd 容器**，先按帧边界扫描再逐帧解压（checksum 交给 libzstd 校验），尾部落单帧不消费、损坏整份作废；一个会话目录只取版本号最高的规范日志。只消费 `session`（id / cwd / parentSession）、`session/title`（最后一个有效标题）、`assistant/message`：用量优先取 `data.usage`，缺失时取 `data.stream` 最后一个 usage chunk，**两处不可相加**；`totalTokens` 只作校验；模型标签为 `source.provider/model`。watermark 恒落在最后一个成功入账的完整帧末尾，明文日志落在最后一个完整换行；同路径文件被原地替换（device + inode 变化）或截断时从 0 重扫。子代理（`parentSession`）的用量归到所属根会话，对话只显示一行并标 `includesSubtasks`。
  - **DSH 逐会话贡献缓存**：每个会话单独累计，换 generation、文件被替换时整体替换该会话贡献，源文件被删则保留历史——因此 generation 切换（官方会保留旧 generation 文件）不会把同一段历史重复计费，日志被清理也不会倒扣历史。贡献随本地用量快照一起持久化，与日 / 对话 / 周期聚合、扫描进度同代。
  - Antigravity：`~/.gemini/antigravity{,-cli,-ide,-backup,-acp}/conversations/*.db` 与 `~/.config/antigravity/conversations/*.db`（SQLite，只读，打不开时退回 immutable 只读）。App / IDE / agy CLI 同一种库结构，合并为一个服务。每次模型调用取 `gen_metadata` 的 usage 及其重试，缺失时用 `steps.metadata` 的 usage 与重试补齐；input 为未命中缓存的输入，cacheRead / cacheCreation 单列，output 已含 thinking。去重身份按 response id → provider message id → message id 取一个，都没有时 `gen_metadata` 行用行号兜底，`steps` 行不计。时间取调用自身时间，缺失时依次退到关联 step、对话创建时间、文件修改时间。模型名优先取记录里的名字，只有占位编号或 `gemini-pro-default` 这类通用名时按编号表推断。对话标题优先读 GUI 的 `annotations/<对话 ID>.pbtxt`，再读取 GUI 的 `agyhub_summaries_proto.pb` 自动标题，最后兼容 `conversation_summaries.db`，标题单独变化也会更新，项目取对话元数据里的工作区路径。按对话文件签名（含 WAL）增量，文件变化时整段替换该对话贡献，文件删除时保留历史。不支持生成计时。
- **Pi / OpenCode / DSH 无订阅额度**：不进入额度轮询、Popover 额度区、菜单栏、悬浮窗、Onboarding 与额度页；仅在主窗口用量统计与对话页展示。打开「包含 Pi、OpenCode、DSH 中的 Codex 订阅用量」后，其中的 Codex 订阅用量计入额度用满预估与 Popover Codex 卡的花费。
- **Codex 模型渠道**：存储及展示保留完整渠道前缀，例如 `commandcode/deepseek/deepseek-v4.1-flash`；厂商归入 Command Code，使用工具仍为 Codex。同一模型的不同渠道分别统计。裸模型及模型末段的日期后缀处理沿用既有规则，定价时单独去前缀匹配价格表；不使用 `session_meta.model_provider` 推测调用渠道。
- **Codex 历史标识修复**：首次增量采集前按已提交扫描进度重放现存日志，只修复可验证的旧模型组，保持四类 Tokens、请求数、原金额及费用分项不变。日桶及旧周期桶混合多个渠道时，以可独立验证的对话金额拆分；同一对话桶混有多个渠道且金额不能拆分、周期只能取到对话的一部分金额、日志缺失或任一投影不匹配时，该旧模型的全部旧桶保留并记录原因，不猜渠道、不按现价重算。迁移结果和原扫描进度随同一快照提交，重复启动不重复累计；读不到的历史不妨碍其他可验证模型迁移或后续新调用采集；日志暂时读不到（读取失败、目录不可访问、扫描中被移走）时不提交迁移结果，本次运行内新调用仍按旧模型名记录，下次启动重试。Claude 等其他数据源不参与这次标识修复。
- 增量逻辑：每个文件按 `mtime + offset` 维护 watermark，未变化直接跳过；文件被截断时 offset 归零重扫，去重由全局 seen 兜底。
- 聚合：按 `(day, app, model, speed)` 在内存中累加；持久化到本地用量快照 `usage-history/current.json` 的日聚合分区。总 Tokens 永远使用日志原始值，Fast 的计费等效 Tokens 按独立倍率另算，不能回写或放大总 Tokens。
- 对话聚合：同一批扫描同时按 `(conversation, day, model, speed)` 聚合并写入本地用量快照的对话分区，不保存聊天正文。Codex 以 `session_meta.id` 为对话 ID，标题优先取 `~/.codex/session_index.jsonl`，分页历史续写的分段按 `history_base.thread_id` 并入原对话一行（不标含子任务），子代理 / Guardian 审查按 `parent_thread_id` 并入父对话一行展示并标含子任务；Claude 以 `sessionId` 为对话 ID，相同 sessionId 的 subagent / sidechain 合并到主对话，桌面端续接产生的各段合成一行（不标含子任务，标题用最近一段），分叉仍是独立对话，标题优先取桌面端起的标题，其次 `~/.claude/history.jsonl`；Pi 以 `type=session` 的会话 id 为对话 ID（缺失时兜底文件名 UUID）；OpenCode 以 `session.id` 为对话 ID（key 前缀 `opencode:`），标题取 `session` 表的 title；DSH 以 `session` 记录的 id 为对话 ID（key 前缀 `dsh:`），子代理会话按 `parentSession` 归到根会话，标题取最后一个有效的 `session/title`。
- 对话项目归属：以规范化完整路径作为项目身份；存在的路径优先归一到 Git 根目录，Claude 同时参考 history project、主会话 cwd 与顶层项目容器，子任务目录不能覆盖主项目。已删除项目保留历史归属；项目目录被移动或改名后，对话改记到现在能解析到的路径；用户主目录 / 根目录归为“无明确项目”，CCBar probe / wakeup 归为“CCBar 系统任务”。同名不同路径不合并。
- 对话费用是按模型 API 公开价格折算的**等值估算**，不是 Codex / Claude 订阅实际账单；无法取得可靠价格时，该部分费用按 `$0` 参与展示，不追加“未定价”标记，Tokens 和请求数仍保留。
- Fast 价格优先使用带明确档位语义的在线字段（LiteLLM 的 OpenAI Priority、models.dev 官方 provider 的 `experimental.modes.fast.cost`），命中不到再回落 `Pricing.swift` 的可指纹化本地规则；绝不把 Standard 价格当 Fast。Codex 按 Priority API 等值费率估算，ChatGPT 信用消耗倍率仍只由本地可靠规则提供；Claude 仅在 Standard/Fast 四项费率比例完全一致时允许推导等效倍率。未收录 Fast 模型，以及 GPT-5.5 / GPT-5.4 完整输入 `>272K` 的 Codex Fast 请求，保留原始 Tokens、档位和请求数，无法计算的费用按 `$0` 展示。GPT-6 与 GPT-5.6 的 Fast 长上下文按官方价计。未收录倍率时计费等效 Tokens 为 0、倍率显示 `—`。
- 价格表：GPT-5.6 / GPT-5.5 / GPT-5.4 阶梯价（完整输入 `>272,000` 时该次请求全部用长上下文价）、Gemini 3.1 Pro 阶梯价（阈值 `200,000`）、Claude Haiku 5.5 阶梯价（阈值 `100,000`）、Grok 4.7 阶梯价（阈值 `256,000`）、GPT-5.5 Pro 固定本地价（输入 / 缓存读取 / 输出为 `$30 / $30 / $180`，无缓存折扣）、Claude Sonnet 5 固定价与 Sonnet 5.5 自 2026-10-07 起的缓存读取降价等少数需要特殊规则的模型继续手工维护在 `Core/Usage/Pricing.swift`，不受远端数据影响。**Google Gemini、Cursor / xAI、Z.ai、MiniMax 的价格也全部来自本表**：远端目录只收 anthropic / openai / deepseek，这几家厂商在远端永远命中不到。Claude Opus 4.6/4.7 Fast 价格仅保留用于历史日志计价。Claude 缓存写入缺少 TTL 明细时全部按默认 5m 估算；Codex 缓存写入字段本地日志未提供时费用估算为 0，不推测。其余 Standard / Fast 模型由内置价格表 + 后台自动拉取的 LiteLLM / models.dev 远端价格目录共同提供：常规 24 小时检查不变；扫描发现缺价的 Standard/Fast 模型时后台绕过 24 小时检查刷新一次，同一 app/model/speed 24 小时内最多一次（手动重算时为 30 分钟）；设置页也可手动更新。新价格只在扫描安全边界提交，新条目按当前价格计，历史费用由自动重算对齐（规则见 §11「历史保护与恢复的行为边界」）。无网络或远端不可用时保留旧快照并降级为内置表，不影响离线使用。命中不到任何价格源时 token 仍记录、费用按 0 汇总。定价模型名归一化（不作为 Codex 存储身份）：循环剥 `openai-codex/`、`openai/`、`anthropic/`、`deepseek/`、`opencode-go/`、`commandcode/`、`command-code/`、`antigravity/`、`z-ai/`、`zai/`、`minimax/`、`deepseek-account/`、`deepseek-official/` 前缀（后两个是 DSH 的 DeepSeek 账号登录 / 官方 API Key 路由名；Command Code 网关标签可能是 `commandcode/deepseek/...`、`commandcode/z-ai/...` 多层，剥完外层需继续剥内层），以及 `@YYYYMMDD` 或 `-YYYY-MM-DD` 日期后缀，本地与远端目录共用同一套规则。

## 7. 主窗口 — 统计

- 主窗口为普通 macOS 窗口，最小 1040×520，含顶部 TabView：统计 / 设置。
- 入口：Popover 的统计 / 设置图标、菜单栏的 ⌘1 / ⌘, 命令；从 Dock、应用程序、Launchpad 或 Raycast 启动 / 重新打开 CCBar 时，主窗口置前并固定切到统计 tab；⌘R 触发立即刷新。开机自动启动保持静默，首次启动仍先展示 Onboarding。
- 统计 tab：
  - 侧栏：服务过滤（All / Codex / Claude Code / Antigravity / Cursor / Pi / OpenCode / DSH，仅列出设置中启用的服务），视图切换（概览 / 对话 / 项目 / 额度）。统计页只做「看」，不提供合并、拆分、重命名、隐藏项目等编辑操作。Cursor 没有本机会话，进入对话或项目视图时服务筛选自动回退到 All；额度视图整页随服务筛选变化：All 显示 Codex 与 Claude Code，单选 Codex / Claude Code 只显示对应周期卡与时间线，选 Antigravity / Cursor / Pi / OpenCode / DSH 显示「暂无额度数据」空态。
  - 顶部两级 segmented Picker：**粒度（日 / 周 / 月）是上级**，决定「一个统计单元」是一天、一周还是一个月；**时间范围是下级**，选项随粒度切换——日：Today / Yesterday / 7d / 30d / This week / This month / Year / All / Custom（日粒度额外保留三档自然周期，用于按天分桶只统计本周 / 本月 / 本年）；周：This week / Last week / 4w / 12w / All / Custom；月：This month / Last month / 6m / Year / All / Custom。概览所有面板（KPI、Token 拆分、用量构成、高消耗对话、用量柱状图）都按所选范围统计，柱状图按粒度分桶。切换粒度时范围自动收敛到新粒度的第一档，All / Custom 三个粒度共用、切换时保留。周范围与周分桶的周起点统一为周一，月按自然月；范围边界处被截断的不完整周 / 月不补全、不标注。粒度与范围在概览、对话、项目三个视图之间共享，切换视图不丢失选择。
  - 自定义：两个 DatePicker（仅在 Custom 时出现）。
  - 金额统一称为「费用」（Cost）：按 API 公开价格估算，对订阅用户只作参考，界面不再额外标注口径。
  - 主窗口默认 1440×900。概览在默认窗口下一屏看完、底部不留空：用量柱状图那一排吃掉剩余高度，窗口放大时图表变高，不够高时降到下限后整页滚动；项目详情的用量图、额度页的折线图同理。模块顺序：KPI 行；每日用量（约 2/3 宽）+ Token 拆分；用量构成（约 5/9 宽）+ 高消耗对话。画布窄于并排断点时两两改为上下排列。
  - KPI：总 Tokens / 费用 / 各可见服务的 费用卡（Codex / Claude Code / Antigravity / Cursor / Pi / OpenCode / DSH 按「统计服务」配置增减）一行排列；每张带相对对比区间的 delta 百分比（本周 / 本月 / 本年对比上一周期的同样天数，其余范围对比上一同长度区间）。服务卡主数字用中性色，识别色只留在标签前的 tile 上。Cursor 的 `chargedCents` 仅作为内部费用数据源。
  - Token 拆分：保留原始总 Tokens 口径，另列 Fast 原始 Tokens、计费等效 Tokens、Fast 估算费用（概览只占一行；倍率与 Fast 占比在对话详情查看）。费用及 Popover 今日/本周费用自动包含可定价的 Fast 溢价，Popover 不增加字段。
  - 用量趋势：堆叠柱状图（各可见服务），用 SwiftUI Charts，柱子按顶部粒度为日 / 周 / 月；标题随粒度显示每日 / 每周 / 每月用量。所选范围只覆盖一个周期（日 · 今天 / 昨天，周 · 本周 / 上周，月 · 本月 / 上月，以及不跨周期的自定义）时，图表自动扩展为近若干周期的上下文（日粒度近 30 天，周 / 月粒度近 14 个周期），所选周期全彩、之前的周期降透明，KPI 与其他面板口径不变。Cursor 选择有限日期范围时，未覆盖的历史（含上下文窗口）按月静默补拉；All 只使用现有缓存，不做无界回溯，也不新增加载、覆盖范围或不完整提示。
  - 用量构成：替代原按服务 / 按模型 / 按提供商三个面板。标题右侧切换维度 `服务 / 提供商 / 模型 / 项目`，默认服务，切换只影响本面板。顶部 8pt 占比条按行依次拼接，合计 Tokens 与 费用放在面板底部；列表列为色块、名称与副标、Tokens、费用、占比、平均输出速度、缓存命中率（末列），四个维度统一显示输出速度，按各行有效请求的输出 Tokens 总和除以对应耗时总和计算，无可计请求及「未归属」行显示 `—`，排序与占比按「设置 → 外观与显示 → 统计 → 排行口径」（默认 Tokens，可选费用；选费用但全部无价时占比按 Tokens）降序。四个维度均列出全部行：服务按可见服务；提供商全部列出，「其他」提供商排在最后；模型对已确认的同一型号跨标识与服务归并，未知标识不猜测合并；项目全部列出，无明确项目与 CCBar 系统任务排在普通项目之后，最后一行「未归属」。列表区固定高度、行多时在面板内滚动，切换维度或展开提供商、模型都不改变面板高度，不挤压上方图表。输入 / 输出 / 缓存读取明细不在本面板展示，见 Token 拆分面板。点击：服务行切换侧栏服务筛选；提供商行（含「其他」）就地展开该提供商下的模型，子行显示 Tokens、费用与输出速度；模型行就地展开各服务的原始模型标识及其用量、费用和输出速度；项目行跳到项目页并选中；「未归属」跳到项目页的未归属详情。「未归属」行的副标说明「Cursor 远端用量、补录和早期历史，没有项目信息」；项目维度底部合计行右侧「全部项目 ›」进入项目页。提供商归属规则：前缀优先（`openai/`、`openai-codex/` → OpenAI，`anthropic/` → Anthropic，`deepseek/` → DeepSeek，`opencode-go/` → OpenCode-Go 单列，便于区分 opencode 内花的钱，`commandcode/`、`command-code/` → Command Code 单列，便于区分 Command Code 会员/网关内花的钱），无前缀时按模型名关键词 / app 兜底（Codex → OpenAI、Claude → Anthropic），其余归「其他」。纯展示层推导，不改动定价与存储。
  - 高消耗对话：按排行口径取范围内前 5 个本机对话，标题旁注明「前 5 个占 Tokens X%」（费用口径为「占费用」）。每行为序号、服务色块、标题、`项目 · 分支 · 日期`、按第一名归一的中性灰金额条；右侧大号数字为口径值（Tokens 或费用），次级为另一项与占比。点击行跳到对话页并选中该对话；「全部对话 ›」跳到对话页并按排行口径排序。
  - 当前额度语义由统一 `QuotaSnapshot` 提供；紧凑入口展示主要额度，详细入口按主/次/模型专项额度展示，颜色按状态色逻辑。
  - Conversations：左侧列表按所选时间范围展示对话标题、项目、服务、模型、请求数、Tokens 与估算费用；全 Fast 对话显示 `Fast` 徽标，部分 Fast 对话显示 `Mixed`，纯 Standard 和仅未识别档位不加列表噪声。支持 Codex / Claude / Pi / OpenCode / DSH 服务筛选、单项目筛选、标题/项目搜索、最近/Tokens/费用排序和每次 200 条渐进加载；Cursor Dashboard 没有本机会话 ID，不进入本页。项目菜单区分正常（含受保护目录下未验证存在的项目）、已不存在、无明确项目和 CCBar 系统任务；为避免触发系统文件夹授权弹窗，桌面/文稿/下载/音乐/图片/影片等保护目录下的路径不做文件系统检查，仅按日志中的路径字符串归组。右侧详情固定展示该对话全部时间的四项 Token、缓存命中率、各速度档位的请求数/原始 Tokens、Fast 计费等效 Tokens、Standard/Fast 费用、四项最终费用、模型构成（Claude Code / Codex / OpenCode / DSH 对话每个模型附平均首字延迟与输出速度；Pi / Antigravity 只附输出速度，Pi 有计时插件记录时同时附首字延迟）与完整时间信息。
  - 首字延迟与输出速度：除 Pi 外只用各 Agent 原生日志自带的时间字段，不依赖插件。首字延迟 = 请求发出到收到第一个 token；输出速度 = 输出 tokens（含思考 tokens）÷ 输出时长；Antigravity 使用原生 `streaming_duration`，其他服务使用首字之后到输出结束的时长。两项按各自有效样本的总量相除。Codex、DSH、OpenCode 能定位首字的请求都计入；Claude Code 只有 2.1.292 起、以 thinking 开头的消息能算出首字。Pi 原生日志只有请求总耗时（`durationMs`，旧日志退回 `message.timestamp` 到条目落盘时间的差），包含首字等待，算出的速度偏低：默认不计入，打开「设置 → 外观与显示 → 统计 → 估算 Pi 输出速度」后才按它近似计算，含近似值的速度前缀 `≈` 并带悬浮说明误差原因。用户可以装 Pi 计时插件（设置里点「计时插件说明」查看插件写法，复制后交给 AI 编写）：插件在 assistant 消息上附加 `ccbarTiming`（首字时长、首个到最后一个流式片段的时长），随消息写入会话 JSONL；有这条记录的请求始终按它精确计算首字延迟与输出速度，不受开关影响。推理不流式输出的模型（只返回加密 reasoning）推理 tokens 计入输出、时间却落在首字之前，插件计时下速度会偏高。Cursor 只有远端计量，不计速度。没有可用耗时的请求不计入，输出不足 100 tokens 或输出时长不足 0.5 秒的请求不计输出速度。tokens 用 API 返回值、请求形态是 Agent 场景，数值只适合比较本机的模型与时间段，界面不与公开榜单并列。升级后自动重建一次给现存日志补上数据，日志已删除的对话没有这两项。对话页刷新只扫描本地日志，不等待额度或服务状态网络请求。 对话页的项目身份与项目页一致（worktree 计入主仓库），从概览或项目页跳来时会清空搜索并按目标选中对话、切换到排行口径排序或按项目筛选；对话详情的模型构成按排行口径排序。
  - 项目：左侧项目列表（搜索项目名或路径、粒度与范围菜单、项目数、按 费用 / Tokens / 最近活跃排序，默认值跟随排行口径，菜单切换只作用于本次查看），每行显示项目名、徽标（含 N 个 worktree / 已不存在 / 非 Git 目录）、路径尾段、大号口径值（Tokens 或费用，按最近活跃排序时跟随排行口径）、`另一项 · 最近活跃` 和按服务色分段、按占最大值比例缩放的工具构成细条；「无明确项目」（从主目录或临时目录启动）与「CCBar 系统任务」固定排在末尾；列表底部固定一行「未归属」。右侧详情：项目名、Git 徽标、完整路径与「在访达中显示」；KPI 为 Tokens、费用（带 delta）、对话数、活跃天数（`活跃 / 范围天数`）；一行全部时间合计与首次使用日期；每日用量（按服务堆叠）与「工具与模型」；分支表与前 3 个高消耗对话（「在对话页查看 ›」按该项目筛选）；含 worktree 时显示只读的「仓库与 worktree」（主仓库与各 worktree 的路径、分支、用量）。详情里的模型、分支、worktree、高消耗对话和工具占比都按排行口径排序 / 计算。
  - 项目归属：项目身份取规范化后的仓库根路径，与对话页一致；worktree 自动计入所属主仓库，不需要用户操作；读不到主仓库信息或位于受保护目录时按独立项目显示，不为判断归属触发系统授权。同一仓库克隆到两处、目录搬家等情况按不同项目显示，不合并也不提供合并建议。Cursor 远端用量和补录的按天汇总数据没有项目信息，计入「未归属」，不分摊到任何项目。分支来自日志：Claude Code、Codex、OpenCode 记录分支，Pi、DSH 显示「无分支信息」。
  - 未归属详情：说明「这些用量计入概览总量，但不出现在任何项目里」；KPI 为 Tokens、费用与占概览总额比例；来源两行各自显示金额与原因——Cursor 远端用量（Cursor 只提供账号级计量，附「在概览中筛选 Cursor ›」）、补录与早期历史（只有按天汇总的数据，注明日期区间与服务）；两行之和等于未归属合计。每日图 Cursor 用服务色，补录与早期历史用灰色斜纹。
  - 项目页状态：首次整理（无对话缓存且正在扫描）显示「正在整理历史对话」、进度条、已处理的会话文件数与占位行；再次扫描保留旧内容，顶部显示扫描指示；范围内没有项目时列表区显示文件夹图标、「今天还没有项目用量」（非今天范围为「该范围内没有项目用量」）、数据来源说明和「查看近 30 天」，底部「未归属」照常显示；项目路径已不存在时显示「已不存在」徽标，历史数据照常展示。
  - 额度：原 Timeline 与 Cycles 合并为一页。顶部「额度用满预估」为 Codex 5 小时、Codex 周、Claude 5 小时、Claude 周四张卡（宽画布一行排列，独立成段便于截图分享，标题行一句话说明估算口径），每张含标签与重置倒计时、用满预估（Tokens · 费用）及可信度、官方已用比例进度条、`已用 X · $Y` 与右侧 `N%`（悬浮说明「服务端返回的额度已用比例。」）；空态沿用定向空态。额度页不展示项目名、项目图例或悬浮项目提示。进度条长度直接反映官方已用比例，进度条与 `N%` 统一按剩余额度着色（≥20% 石墨灰、<20% 橙、=0 红）。周期统计从功能首次启用后开始，不反推此前周期，不读取日聚合或 Claude 补录数据；账号切换按时间段隔离，Claude 用邮箱脱敏哈希区分主账号；预估仅为本机费用推算，不代表官方绝对上限。默认只计 Codex / Claude Code 自己日志里的订阅模型（规则见上方「两类数据」：在 Codex 里用 `commandcode/...` 等其他渠道前缀或 grok、deepseek 等其他厂商模型、在 Claude Code 里用非 `claude-*` 模型的用量不计入；第三方渠道转发的同名模型仍会计入，Popover 花费同理；按模型名在展示时过滤，已有历史立即按此口径显示，不需要重算）；打开「设置 → 外观与显示 → 统计 → 包含其他 Agent 中的 Codex 订阅用量」后，Codex 卡同时计入 Pi、OpenCode、DSH 里的 Codex 订阅用量（一律算到 Codex 主账号），标题行口径说明改为「按本机用量（含其他 Agent 的 Codex 订阅用量）和官方已用比例估算，仅供参考。」（只显示 Claude 卡时不改），切换立即生效、不需要重算。下方「今天的额度变化」（周视图为「周额度变化」）右侧为全局 `5H / 本周` 切换，账号分区两列并排（超过两个账号换行、页面滚动），每个分区含原有 header 与指标、折线图（固定高度，加「窗口重置」与「现在」两条竖向参考线）和默认收起的「变动明细 · N 条」（展开时面板向下变长，不压缩折线图）；5H 固定展示今天，周视图按服务返回的重置时刻展示当前和上一额度周期，折线按额度窗口分段，跨周期重置不伪造成消耗事件；账号顺序跟 Provider 自定义序，Codex 副账号始终紧跟 Codex 主账号。
  - 本地日志读取、周期重建或统计持久化真实失败时，统计页顶部显示警告，保留仍可用的已有数据，并提供“打开设置”入口让用户触发重新计算；扫描过程中会话文件被正常归档或清理不算失败、不提示误报警告，错误恢复后警告自动消失。手动重算若被拒或保存失败，设置页重算按钮旁同步提示「保留原历史」与下一步；历史进入只读（快照由更新版本写入）或受限恢复时同样以可见提示说明当前状态。
  - 统计服务显示配置：由「设置 → 服务与账号」里每个服务的「开启」开关决定（Codex / Claude Code / Pi / OpenCode / DSH 默认开启，Cursor 默认关闭，Antigravity 跟随其额度开关）。Codex / Claude Code / Antigravity / Cursor 的额度和用量共用这一个开关，不再分开设置；旧版两项不一致时按「任一项开着就算开启」合并。关闭后该服务从侧栏过滤项、KPI 卡、Token 拆分、用量构成、高消耗对话、项目页和每日用量图表中一并消失，占比分母只统计可见服务（归一化）；全部关闭时用量构成的服务维度显示空态引导。开启 Cursor 才会启动其只读远端刷新；本地服务关闭后仍会被扫描与入库，重新开启后历史数据照常出现。

### 额度提醒

设置 → 通用 → 额度提醒，默认关闭，升级不申请通知权限。监控已启用的 Codex、Claude Code、Antigravity、Cursor、Command Code、OpenCode Go 和 Codex 导入账号，共用剩余百分比阈值（默认 20%，5%～50%，步长 5%）。可选 5 小时／会话、周额度（含模型专属周额度）、计费周期额度，默认全选、至少保留一项；声音默认关闭。旧 Codex 开关和阈值保留，开启后范围扩展到已启用的额度服务。

Codex 监控 5 小时／周窗口；Claude Code 监控 5 小时、全模型周额度及有效的模型专属周额度；Antigravity 监控 Gemini／Claude 的 5 小时与周窗口（兼容非分组响应的独立 Gemini 字段）；Cursor 监控 Total／Auto／API 计费周期；Command Code 与 OpenCode Go 监控 5 小时、周及已解析的月额度。缺失、未启用或无法识别的窗口不推算为耗尽，无限额度不提醒；Cursor 超过套餐上限按剩余 0% 提醒。

只在真实额度请求成功后检查，剩余严格低于阈值才提醒；开启时已有缓存不立即触发，等下一次成功刷新。同一实际账号、同一窗口、同一识别周期最多提醒一次，同次刷新多个窗口首次不足合并成一条。关开、改名、切换默认/导入入口、修改阈值和语言不重置记录。没有可靠重置时间时，需两次相隔至少 60 秒的成功观察确认恢复，才允许将来再次变低时提醒；App 错过整个恢复阶段可能漏提醒。

首次主动开启申请系统权限，拒绝后保留 App 内开启状态并引导去系统设置；发送前重查授权，遵从系统通知样式、声音和专注模式。点击通知打开统计主窗口，首次引导优先；不定位具体账号。进入隐私模式时清理本功能的待送达/已送达通知，未来正文复用界面匿名账号编号；已被看到或系统同步的内容不能保证收回。

仅身份可确认的 API 成功结果参与通知；Claude CLI 兜底及 Antigravity CLI 的 JSON 没有可核实身份，保留额度展示但不触发通知。身份可确认的 Antigravity 云端响应若含 Argon 独立周桶，按模型周额度单独监控。Claude 缺账号 UUID、Antigravity 未取得邮箱、Command Code 缺 user ID 时跳过提醒；不以 token 作为通知身份。OpenCode Go 没有账号资料，以 API key 的不可逆摘要区分账号。通知随原有成功刷新发现变化，无额外轮询；锁屏/息屏仍按原有降频，睡眠及退出期间不能检测新下降。提醒记录单独保存，损坏、版本不兼容或初始化后丢失时暂停；设置页可主动重建，先备份原文件，各入口每个窗口首次成功结果中的低额度只建立已提醒基线，后续新增或暂未选择的窗口也各自建立一次基线。实际 macOS 权限、前后台展示、重启及 ad-hoc 分发包通知行为尚待手动验收。

### 应用更新

主动检查发现新版后，独立原生弹窗展示当前/目标版本、发布日期和更新内容（与 GitHub Release 正文一致：最新版说明加近期新功能，跨版本升级不列中间版本）；点击「下载并安装」后自动下载、验证、保存状态、退出、安装与重新启动，无需第二次确认。可关闭窗口推迟安装、跳过版本、取消下载或失败重试，不另设「稍后 / 后台继续」按钮。后台发现新版时仅在菜单栏弹出面板提供版本号与「下载」按钮，不抢前台；Popover 按钮只打开更新窗口，文案固定，不显示任务状态或其他更新提示。设置页保留检查/查看入口，任务状态及错误统一在更新窗口显示，不保留升级成功提示。关闭下载窗口继续任务。正常退出与更新均等待数据保存，失败取消退出。发布包、更新源及日志均签名验证；首个支持应用内更新的版本须手动安装一次。

**历史保护与恢复的行为边界**：

- 日聚合、对话档案、周期用量、扫描进度与 DSH 逐会话贡献共享同一 `snapshotID` 并同处一份快照：要么一起生效，要么一起保持原样，磁盘上不存在「新进度 + 旧汇总」这类组合。
- 升级后把旧的分散缓存一次性合成快照（只读旧文件，不修改、不删除）。旧文件缺失 = 没有这份数据；版本不受支持或损坏 = 该数据不可用并如实报告，不当作空数据继续覆盖。
- `current.json` 损坏或被截断时整体回退到 `previous.json`，绝不混合两代数据；损坏文件移入 `quarantine/` 保留证据。`current.json` 由更新版本写入时进入只读模式，只展示不覆盖。
- 主历史可用但扫描进度不可信（例如 Caches 被清理）时进入**受限恢复**：历史照常展示，进程内只做一次完整核对，通过才采纳新进度；不通过就保留历史、停止自动全量重扫，仅提示用户手动重算。
- 历史重算（自动或手动「重新计算用量」）在全量重扫的独立副本上生成结果，成功持久化后才切换。规则是**日志还在的对话以日志为准，日志已删除的对话保留原用量**：新价格、新解析规则对日志还在的部分逐条生效；日志已删除的对话按保存的汇总用量和当前价格表重新计费（缺少逐条明细，金额为估算）。日志读取不完整或写盘失败时保留原历史并如实报告；重算期间有会话在写日志不影响结果。
- 源日志被删除时已保存的历史不倒扣：普通增量采集和重算都保留（OpenCode / DSH / Antigravity 由逐会话贡献保留）。续接 / 分叉对话复制的消息只计一次，归给原对话；原对话日志被删、续接对话还在时不重复计入。为此按对话记录已计入的消息 ID（只存摘要，不存原文），跨轮去重没有条数上限。升级到这一版之前就已删除的对话没有 ID 记录，重算时按天核对防重复，同一天同一模型下有多个被删对话时可能不精确。
- 周期缓存里指向已被合并 / 剔除的周期记录的残留桶不算缓存失效：只丢弃这部分，能由最近窗口重建补回的自动补回，补不回的在设置页「重新计算用量」旁提示「周期用量不完整」，交给用户决定何时重算，不再为此自动全量重扫。
- 历史自动按最新价格与统计规则重算，用户不需要知道价格表什么时候改过：
  - 升级 App 后本地价格表或统计规则有变化（包括首次升级到这一版），启动后自动重算一次。
  - 远端价格目录里用过的模型价格变了：原来缺价的用量拿到价格、或用户刚在设置页手动更新价格目录时立即重算；其余情况距上次完整重算满 24 小时才重算。
  - 有缺价用量时后台自动查一次远端价格，同一模型 24 小时最多一次。
  - 自动重算没有完成（日志读取失败等）时，24 小时内不再自动重试。
  - 重算期间统计页顶部显示「正在重新计算用量…」，设置页「重新计算」按钮显示进度并禁用。设置页「重新计算用量」保留为手动兜底，行为与自动重算相同。
- Cursor 远端计量独立于本地快照，本地恢复 / 重算不影响其桶、账号隔离与覆盖区间。

## 13. 风险 / 待持续关注

1. **非公开接口稳定性**：`wham/usage` / `oauth/usage` 字段可能随时调整，解析器需要保持容错。
2. **Keychain 弹窗**：首次读 `Claude Code-credentials` / `Claude Safe Storage` / `Cursor Safe Storage` 系统会弹一次授权窗，引导文案已加。三者都经系统 `security` 工具读取，授权不随 ad-hoc 签名的版本更新失效；代价是对 `Claude Safe Storage` / `Cursor Safe Storage` 选「始终允许」后，本机同一用户的其他进程也能经 `security` 静默读到这两把密钥（`Claude Code-credentials` 本来就由 Claude Code 经 `security` 写入，没有新增暴露）。
3. **价格表漂移**：当前对齐 cc-switch / CodexBar 2026 上半年价位；模型迭代后需要同步。
4. **JSONL 量级**：长期使用后 `~/.claude/projects` 可达数百 MB；增量 watermark 保证日常扫描时间可控。价格或统计规则变化后的自动重算是一次全量扫描（2026-08-30 实测 194MB 日志约 24 秒 CPU），升级 App 时最多一次，远端调价 24 小时最多一次。
5. **签名与公证**：发布产物走 `scripts/build.sh` 的 ad-hoc 签名，没有 Developer ID 证书也没有公证，用户首次启动需在「系统设置 → 隐私与安全性」放行一次（README 有说明）。若日后需要免放行分发，仍要补 Apple Developer 证书与公证流程。

### 历史恢复的异常边界

- 两份新快照失效或缺失时停止本地采集，保留原文件；已经使用新存储后不回读过期旧缓存。格式不兼容时要求使用兼容版本，有有效备份才展示备份。
- 从 v1.0.64 之前的版本升级时，旧日用量缓存版本过旧、损坏、为空或缺失，按首次安装从本机日志全量重扫，与升级前的版本处理一致；已被清理的日志对应的用量无法计入。旧文件保留不动。
- 对话历史或扫描进度不可信时显示可用历史并暂停采集，核对通过才恢复。日志新增或缺失导致核对失败时，不能承诺点击重算即可恢复，也不提供强制丢弃历史按钮。
- 设置页明确显示核对失败；费用重算成功但周期归属有差异时显示周期完整性未确认。DSH 贡献不可用时显示该来源暂停，其他来源继续采集。
