# cc-bar 产品需求

> 描述当前已交付版本的功能范围与边界。新需求迭代时以本文为准；与代码不一致以代码为准并同步回这里。

---

## 0. 产品定位

- **形态**：常驻菜单栏的小工具（Accessory App，默认不占 Dock；打开主窗口期间临时显示 Dock 图标，关闭后恢复）。
- **平台**：macOS 14 Sonoma+（依赖 SwiftUI `MenuBarExtra(.window)`、`@Observable`、`SMAppService`）。
- **设计**：以 macOS HIG 为底座，关键信息层（百分比、进度、KPI、HUD）按设计稿落地自绘组件；非关键层（Picker / Toggle / DatePicker / TabView / Material）全部用系统默认。
- **一句话价值**：装上它 → 不打开 CLI 也能随时看到 Codex / Claude Code / Antigravity 的当前额度，以及启用后的 Cursor Total / Auto / API 额度，并查看 Codex / Claude Code / Pi / OpenCode / DSH 的本地 Token 与费用；启用 Cursor 统计后，还可查看该 Cursor 账号全设备的服务端计量用量。

## 1. 账号自动识别

- 启动时扫描本机已有的 Codex / Claude Code / Antigravity / Cursor / Command Code 凭据：
  - Codex：`~/.codex/auth.json`。支持两种凭据形态：① OAuth 模式（`tokens.*`，解析 JWT 拿邮箱 / plan / accountId，到期自动续期）；② personal access token 模式（顶层 `personal_access_token`，即 ChatGPT Team/Enterprise 后台创建的 Codex 访问令牌，不透明、不续期，身份由 `wham/usage` 响应回填）。导入「其他 Codex 账号」时也接受这两种形态的粘贴。
  - Claude：先读 `~/.claude/.credentials.json`；不存在则读 macOS Keychain 通用密码项 `Claude Code-credentials`（service name）。邮箱兜底从 `~/.claude.json` 顶层 `oauthAccount.emailAddress` 读取。
  - Cursor：只读 `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` 的 `cursorAuth/accessToken`，解析 JWT 仅用于识别账号；不读取 refresh token、不调用 OAuth、不写 Cursor SQLite 或 cc-bar Keychain。
  - Antigravity：`~/.gemini/jetski-standalone-oauth-token`（优先，Antigravity 生态真源：agy CLI / IDE 插件登录即写此文件）或 `~/.gemini/oauth_creds.json`（兜底，旧版 Gemini CLI 遗留），账号身份由云端 `loadCodeAssist` 响应回填，`refresh_token` 自动续期（双 client 兼容，Cloud Mode 无需本地 IDE）。
  - Command Code：5 级只读自动扫描，按 `~/.commandcode/auth.json` → `~/.pi/agent/auth.json` → `~/.local/share/opencode/auth.json` → 环境变量 `COMMAND_CODE_API_KEY` / `COMMANDCODE_API_KEY` → macOS Keychain 手动 Key 的顺序取第一个命中的；也可在设置中把凭据来源切成「手动 API Key」，此时只读 Keychain。
- 不做 App 内登录流程。前提：用户已经在终端跑过 `codex login` / `claude` 登录。
- 用户可在「设置 → 账号」勾选要显示的额度 Provider；Codex、Claude Code 默认开启；Antigravity 在新安装首次启动时检测到凭据才默认开启，未检测到则关闭（已装机用户保留原设置）；Cursor 与 Command Code 的 Provider 开关默认关闭，启用后才查询远端接口。Command Code 作为订阅额度 Provider，进入「设置 → 账号」、Popover、菜单栏与桌面悬浮窗；不进入主窗口用量统计。
- 首次启动若不存在 `~/.claude/.credentials.json`，且尚未提示过，会先弹一次说明性 Alert（"接下来 macOS 会弹 Keychain 授权窗口，请选择始终允许"），再触发系统 Keychain 弹窗。

## 2. 菜单栏标签

- 标签是模板图像（template NSImage），自适应深浅菜单栏。
- 顺序固定：**Codex → Claude Code → Antigravity → Cursor → Command Code**。
- 每段为 `<服务 logo>  <百分比>`：
  - Logo 用项目内置的 `codex.svg` / `claude.svg` / `antigravity.svg` / `cursor.svg` / `commandcode.svg`（菜单栏会做模板化变灰）。
  - 百分比用 `monospacedDigit`。
- 设置项：
  - 显示哪个服务（Codex / Claude Code / Antigravity / Cursor / Command Code，可分别开关）。Cursor 始终只显示 Total；Auto / API 详见 Popover，不能被伪装为周额度。Command Code 支持 5 小时与周额度。
  - 显示哪个额度窗口：主要额度 / 周窗口 / 两者。主要额度通常是 5 小时；服务端临时只返回周额度时自动显示周额度。两者相同时只显示一次。
- 都关闭时仍保留一个占位 logo，避免菜单栏完全消失。

## 3. Popover 总览

- 点击菜单栏图标弹出宽 340pt 的窗口。
- 顺序：Codex → Claude Code → Antigravity → Cursor → Command Code（每个服务一个 block，仅显示已启用项，用 Divider 分隔）。
- Header 一行：标题「Usage / 用量」+ 副标题（最近一次刷新相对时间 / 刷新失败 / 等待数据）+ 状态点（live / stale / offline）+ 四个一级图标按钮（刷新 / 统计 / 设置 / 退出），没有 kebab 菜单也没有 footer。
- 每个 block 字段：
  - 服务 tile + 服务名 + 副标题（Provider · Plan）。
  - 主要额度：32pt 剩余百分比 + 16pt `%` + 动态窗口标签 + 进度条 + 重置倒计时；各 Provider 复用既有「今日 cost」+「本周 cost」展示位。
  - 次要额度：存在且与主要额度不重复时显示缩小版进度条；Claude 继续展示 Fable 等模型专项周额度。
  - Cursor：主额度为 Total，次要条展示 Auto 与 API；今日 / 本周费用汇总已成功拉取的远端计量数据，位置和样式与 Codex / Claude 一致；有覆盖或字段缺口时保留当前金额并在后台补拉，完全没有远端快照时才显示既有占位。Unlimited 以 `∞` + `UNLIMITED` 标签表示,不渲染伪造百分比或进度条。
  - Antigravity：主条为 Gemini 5 小时窗口（标签 Gemini 5H），副条 Gemini 周（Gemini WK），辅助行 Claude 5H / Claude WK（按官方 retrieveUserQuotaSummary 分组展示，Gemini 在前）；解析 `loadCodeAssist` + `retrieveUserQuotaSummary`（权威分组）+ `fetchAvailableModels` + `retrieveUserQuota`（兜底分桶），失败保留快照。
  - Command Code：主额度为 5 小时窗口，次要条展示周窗口，两者的 cap 与已用量都由服务端 `windowLimits` 返回，不在本地写死；GOAT 套餐额外有一条月度额度（按月总额 70 换算剩余比例，重置时间取订阅的 `currentPeriodEnd`）。不展示用量费用。
  - 失败时沿用 block 下方既有短提示；Cursor 与 Command Code 仅显示通用失败状态，不直出远端技术错误原文。
- 关闭全部服务时显示"未启用任何服务 / 到「设置 → 账号」开启"占位。
- 状态点阈值：以当前额度刷新间隔为基准，age ≤ 1.5× 间隔为 live，≤ 3× 为 stale，超过为 offline。

## 4. 桌面悬浮窗（Floating HUD）

- 设置里可勾选「显示悬浮窗」。
- 默认按已启用服务逐行展示 Codex、Claude Code、Antigravity、Cursor、Command Code 的主要额度（18pt tile + 进度条 + 大字百分比）。Cursor Unlimited 只显示 `∞`，不显示 100%。
- 行可分别开关，结果只显示一行 / 全部隐藏。
- 样式：14pt 圆角 + `.popover` material + 0.5pt hairline 描边；无标题栏；不抢焦点；可拖动；始终置顶。
- 位置记忆：拖动后写回 UserDefaults；屏幕外重启时回落到默认右上角。
- 拖到距屏幕边缘 20pt 以内自动吸附到该边。

## 5. 自动后台刷新

- 后台三件周期任务共用**单一时基**（不是各起一条循环）：
  - 额度 API 刷新：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
  - 本地日志扫描：默认 5 分钟，可选「1m / 2m / 3m / 5m / 10m」；启动后仍立即增量扫描一次，手动刷新不受周期限制。已有用户已保存的间隔保持不变。
  - 服务状态：固定 5 分钟，不跟随上面两个设置。
- 调度器每次只睡到最近一个到期任务，醒来时把 5 秒容差内到期的任务一并执行，减少唤醒次数；系统睡眠期间停表、唤醒后立即补跑一轮；屏幕休眠或锁屏期间所有间隔 ×4 降频，恢复可见时立即补一次全量刷新。
- 端点：
  - Codex：`GET https://chatgpt.com/backend-api/wham/usage`，带 `ChatGPT-Account-Id` 头。
  - Claude：`GET https://api.anthropic.com/api/oauth/usage`
  - Antigravity：优先 `POST https://daily-cloudcode-pa.googleapis.com/v1internal:loadCodeAssist` + `retrieveUserQuotaSummary` + `fetchAvailableModels` + `retrieveUserQuota`，主域仅作失败回退（Bearer 直连，token 临期双 client 刷新）；套餐优先读取 `paidTier`，重置时间只使用服务端 `resetTime`。
  - Cursor：`GET https://cursor.com/api/usage-summary`，只携带 Cursor.app 只读登录态构造的 Cookie；401 时最多重读一次本地 SQLite，绝不 OAuth 刷新。
- 限流策略：
  - 同一服务两次成功之间至少 60 秒，周期性触发若间隔不足直接跳过。
  - 收到 429 后该服务进入固定 10 分钟退避（不是指数退避），期间所有请求短路。
  - 手动「立即刷新」可绕过 60s 节流但仍遵守 429 退避。
- 手动刷新会在两种情况下触发一次 Claude CLI 兜底（启动 `claude` 进程，向其 stdin 写入 `/usage`，解析输出）：Claude API 失败且**完全没有可展示缓存**，或 Claude 凭据已过期。CLI 兜底有独立 10 分钟冷却。
- Token 续期：
  - **Codex** 在 access_token 距离过期 5 分钟内用 refresh_token 自动续期，并把新 token 写回原存储位置（`auth.json` 或 cc-bar 自己的 Keychain 条目）。发请求前会重读一次存储，若 `codex` CLI 已自行轮换过就直接采用，不拿陈腐 token 去撞服务端的重用检测。
  - **Antigravity 自动续期**：临期 5 分钟静默用 `https://oauth2.googleapis.com/token` 双 client 刷新并回写 `jetski-standalone-oauth-token`（优先）/`oauth_creds.json`（兜底）。
  - **Claude 不续期**。Anthropic 的 refresh_token 一次性、刷新即轮换，cc-bar 一旦刷新就会把 Claude Code CLI / Desktop 挤下线，因此只读采用它们刷新后的结果。凭据过期时保留上一次额度快照并提示「请打开 Claude Code 刷新登录」，本地 Token / 费用统计不受影响。
- 启动行为：先读本地额度缓存让 UI 立刻有数；启动 7 秒后触发一次额度刷新，之后按调度器节奏轮询；网络或本地服务失败保留已有快照，仅以小字提示。

## 6. 本地用量统计

- 数据源：纯本地 JSONL，**额度 API 不返回历史数据**。
  - Claude：`~/.claude/projects/**/*.jsonl`，解析 `type=assistant` 行；`message.usage.speed` 的 `standard` / `fast` 原样映射，缺失或未来新值记为未识别。同一 `message.id` 跨文件全局去重（sidechain / subagent 会重复引用同一条），seen 集合上限 20000。缓存写入原始 Tokens 继续使用 `cache_creation_input_tokens` 合计；计价时读取 `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens`，分别按当前 Standard / Fast 基础输入价的 1.25× / 2× 计算。
  - Codex：`~/.codex/sessions/**/*.jsonl` + `~/.codex/archived_sessions/**/*.jsonl`，按 `turn_context` 提供的当前 model 给随后的 `event_msg/token_count` 打标签；`thread_settings_applied.thread_settings.service_tier` 的 `priority` / `fast` / `default` 分别映射为 Fast / Fast / Standard，并跨增量扫描保存当前档位。token 用 `payload.info.last_token_usage`，billable input = `input_tokens − cached_input_tokens − cache_write_tokens`。`cache_write_tokens` 兼容顶层及 token details；当前本地日志未提供时按 0，不推测。相同 `total_token_usage` 签名的重复 `token_count` 不再次入账。
  - Pi：`~/.pi/agent/sessions/**/*.jsonl`，解析 `type=message` 的 assistant 行；`message.usage` 直接提供 input / output / cacheRead / cacheWrite / totalTokens。`message.cost.total > 0` 时优先采用日志总价及有效分项；分项与总价只有 JSON 浮点尾差时保留分项并对齐总价。价格缺失或为 0 且有 Token 时，复用统一 Pricing 的在线目录 → 本地价格表补算。compaction / branch_summary 带 `usage` 时一并计入（对齐 pi `/session` 合计口径）。跨文件按 entry id + ISO 时间戳全局去重（fork / clone 复制旧行），seen 上限 20000。模型标签为 `provider/model`，速度档位恒为 Standard。
  - OpenCode：`~/.local/share/opencode/opencode.db`（SQLite，Desktop / CLI 共用，只读）。兼容 v1 `session/message` 和 v2 `session_v2/session_message`；迁移共存时相同消息 ID 优先采用 v2，保留 v1 独有历史，避免重复计费。只计已完成 assistant 的 `cost`（USD）和 `tokens{input, output, reasoning, cache{read, write}}`，reasoning 并入 output；有效 `cost > 0` 优先采用日志总价，分项按价格表占比缩放；价格缺失或为 0 且有 Token 时由在线目录 → 本地价格表补算，未知价格按 `$0` 展示。两版角色 / 模型字段分别解析，模型标签统一为 `providerID/modelID`。会话标题 / 项目来自对应 session 表；分支字段不存在时留空，空标题用 user 文本 / text part 兜底。按会话变动签名重读并替换贡献，消息跨轮完成或用量更新不会漏算或重复累加；读取失败保留旧统计并提示错误。升级旧缓存时只重建现存 OpenCode 会话，不触发其他服务全量重扫。
  - DSH：`~/.dsh/sessions/<项目段>/<会话段>/session[.vN].jsonl[.zstd]`，只读**默认根**（不做 Desktop 自定义数据目录、显式 `DSH_HOME`、Beta home 的自动发现；没有默认日志不能据此断定用户未安装 DSH）。日志是**多帧拼接的 zstd 容器**，先按帧边界扫描再逐帧解压（checksum 交给 libzstd 校验），尾部落单帧不消费、损坏整份作废；一个会话目录只取版本号最高的规范日志。只消费 `session`（id / cwd / parentSession）、`session/title`（最后一个有效标题）、`assistant/message`：用量优先取 `data.usage`，缺失时取 `data.stream` 最后一个 usage chunk，**两处不可相加**；`totalTokens` 只作校验；模型标签为 `source.provider/model`。watermark 恒落在最后一个成功入账的完整帧末尾，明文日志落在最后一个完整换行；同路径文件被原地替换（device + inode 变化）或截断时从 0 重扫。子代理（`parentSession`）的用量归到所属根会话，对话只显示一行并标 `includesSubtasks`。
  - **DSH 逐会话贡献缓存**：每个会话单独累计，换 generation、文件被替换时整体替换该会话贡献，源文件被删则保留历史——因此 generation 切换（官方会保留旧 generation 文件）不会把同一段历史重复计费，日志被清理也不会倒扣历史。贡献随本地用量快照一起持久化，与日 / 对话 / 周期聚合、扫描进度同代。
- **Pi / OpenCode / DSH 无订阅额度**：不进入额度轮询、Popover 额度区、菜单栏、悬浮窗、Onboarding 与额度页；仅在主窗口用量统计与对话页展示（Pi / OpenCode 今日费用仍计入 Popover 今日合计，DSH 不计入）。
- **Codex 模型渠道**：存储及展示保留完整渠道前缀，例如 `commandcode/deepseek/deepseek-v4.1-flash`；厂商归入 Command Code，使用工具仍为 Codex。同一模型的不同渠道分别统计。裸模型及模型末段的日期后缀处理沿用既有规则，定价时单独去前缀匹配价格表；不使用 `session_meta.model_provider` 推测调用渠道。
- **Codex 历史标识修复**：首次增量采集前按已提交扫描进度重放现存日志，只修复可验证的旧模型组，保持四类 Tokens、请求数、原金额及费用分项不变。日桶及旧周期桶混合多个渠道时，以可独立验证的对话金额拆分；同一对话桶混有多个渠道且金额不能拆分、周期只能取到对话的一部分金额、日志缺失或任一投影不匹配时，该旧模型的全部旧桶保留并记录原因，不猜渠道、不按现价重算。迁移结果和原扫描进度随同一快照提交，重复启动不重复累计；读不到的历史不妨碍其他可验证模型迁移或后续新调用采集；日志暂时读不到（读取失败、目录不可访问、扫描中被移走）时不提交迁移结果，本次运行内新调用仍按旧模型名记录，下次启动重试。Claude 等其他数据源不参与这次标识修复。
- 增量逻辑：每个文件按 `mtime + offset` 维护 watermark，未变化直接跳过；文件被截断时 offset 归零重扫，去重由全局 seen 兜底。
- 聚合：按 `(day, app, model, speed)` 在内存中累加；持久化到本地用量快照 `usage-history/current.json` 的日聚合分区。总 Tokens 永远使用日志原始值，Fast 的计费等效 Tokens 按独立倍率另算，不能回写或放大总 Tokens。
- 对话聚合：同一批扫描同时按 `(conversation, day, model, speed)` 聚合并写入本地用量快照的对话分区，不保存聊天正文。Codex 以 `session_meta.id` 为对话 ID，标题优先取 `~/.codex/session_index.jsonl`；Claude 以 `sessionId` 为对话 ID，相同 sessionId 的 subagent / sidechain 合并到主对话，标题优先取 `~/.claude/history.jsonl`；Pi 以 `type=session` 的会话 id 为对话 ID（缺失时兜底文件名 UUID）；OpenCode 以 `session.id` 为对话 ID（key 前缀 `opencode:`），标题取 `session` 表的 title；DSH 以 `session` 记录的 id 为对话 ID（key 前缀 `dsh:`），子代理会话按 `parentSession` 归到根会话，标题取最后一个有效的 `session/title`。
- 对话项目归属：以规范化完整路径作为项目身份；存在的路径优先归一到 Git 根目录，Claude 同时参考 history project、主会话 cwd 与顶层项目容器，子任务目录不能覆盖主项目。已删除项目保留历史归属；用户主目录 / 根目录归为“无明确项目”，CCBar probe / wakeup 归为“CCBar 系统任务”。同名不同路径不合并。
- 对话费用是按模型 API 公开价格折算的**等值估算**，不是 Codex / Claude 订阅实际账单；无法取得可靠价格时，该部分费用按 `$0` 参与展示，不追加“未定价”标记，Tokens 和请求数仍保留。
- Fast 价格优先使用带明确档位语义的在线字段（LiteLLM 的 OpenAI Priority、models.dev 官方 provider 的 `experimental.modes.fast.cost`），命中不到再回落 `Pricing.swift` 的可指纹化本地规则；绝不把 Standard 价格当 Fast。Codex 按 Priority API 等值费率估算，ChatGPT 信用消耗倍率仍只由本地可靠规则提供；Claude 仅在 Standard/Fast 四项费率比例完全一致时允许推导等效倍率。未收录 Fast 模型以及完整输入 `>272K` 的 Codex Fast 请求保留原始 Tokens、档位和请求数，无法计算的费用按 `$0` 展示；未收录倍率时计费等效 Tokens 为 0、倍率显示 `—`。
- 价格表：GPT-5.6 / GPT-5.5 / GPT-5.4 阶梯价（完整输入 `>272,000` 时该次请求全部用长上下文价）、Gemini 3.1 Pro 阶梯价（阈值 `200,000`）、GPT-5.5 Pro 固定本地价（输入 / 缓存读取 / 输出为 `$30 / $30 / $180`，无缓存折扣）、Claude Sonnet 5 分段生效价等少数需要特殊规则的模型继续手工维护在 `Core/Usage/Pricing.swift`，不受远端数据影响。**Google Gemini、Cursor / xAI、Z.ai、MiniMax 的价格也全部来自本表**：远端目录只收 anthropic / openai / deepseek，这几家厂商在远端永远命中不到。Claude Opus 4.6/4.7 Fast 价格仅保留用于历史日志计价。Claude 缓存写入缺少 TTL 明细时全部按默认 5m 估算；Codex 缓存写入字段本地日志未提供时费用估算为 0，不推测。其余 Standard / Fast 模型由内置价格表 + 后台自动拉取的 LiteLLM / models.dev 远端价格目录共同提供：常规 24 小时检查不变；扫描发现新的缺价 Standard/Fast 模型时立即绕过 24 小时刷新，同一 app/model/speed 30 分钟内最多尝试一次；设置页也可手动更新。新价格只在扫描安全边界提交，**不**自动触发历史重算：自动扫描按当前价格计新条目，历史费用保持旧价，需要对齐时由用户在设置页手动「重新计算用量」（唯一的全量重算入口）。无网络或远端不可用时保留旧快照并降级为内置表，不影响离线使用。命中不到任何价格源时 token 仍记录、费用按 0 汇总。定价模型名归一化（不作为 Codex 存储身份）：循环剥 `openai-codex/`、`openai/`、`anthropic/`、`deepseek/`、`opencode-go/`、`commandcode/`、`command-code/`、`antigravity/`、`z-ai/`、`zai/`、`minimax/` 前缀（Command Code 网关标签可能是 `commandcode/deepseek/...`、`commandcode/z-ai/...` 多层，剥完外层需继续剥内层），以及 `@YYYYMMDD` 或 `-YYYY-MM-DD` 日期后缀，本地与远端目录共用同一套规则。

## 7. 主窗口 — 统计

- 主窗口为普通 macOS 窗口，最小 1040×520，含顶部 TabView：统计 / 设置。

- 统计 tab：

  - 金额统一称为「费用」（Cost）：按 API 公开价格估算，对订阅用户只作参考，界面不再额外标注口径。
  - 主窗口默认 1440×900。概览在默认窗口下一屏看完、底部不留空：用量柱状图那一排吃掉剩余高度，窗口放大时图表变高，不够高时降到下限后整页滚动；项目详情的用量图、额度页的折线图同理。模块顺序：KPI 行；每日用量（约 2/3 宽）+ Token 拆分；用量构成（约 5/9 宽）+ 高消耗对话。画布窄于并排断点时两两改为上下排列。

  - 用量构成：替代原按服务 / 按模型 / 按提供商三个面板。标题右侧切换维度 `服务 / 提供商 / 模型 / 项目`，默认服务，切换只影响本面板。顶部 8pt 占比条按行依次拼接，合计 Tokens 与 费用放在面板底部；列表列为色块、名称与副标、占比、Tokens、费用、缓存命中率（末列），排序与占比按「设置 → 外观与显示 → 统计 → 排行口径」（默认 Tokens，可选费用；选费用但全部无价时占比按 Tokens）降序。四个维度都全部列出、不合并：服务按可见服务；提供商全部列出，「其他」提供商排在最后；模型跨服务按名称合并后全部列出；项目全部列出，无明确项目与 CCBar 系统任务排在普通项目之后，最后一行「未归属」。列表区固定高度、行多时在面板内滚动，切换维度或展开提供商都不改变面板高度，不挤压上方图表。输入 / 输出 / 缓存读取明细不在本面板展示，见 Token 拆分面板。点击：服务行切换侧栏服务筛选；提供商行（含「其他」）就地展开该提供商下的模型；模型行无点击；项目行跳到项目页并选中；「未归属」跳到项目页的未归属详情。「未归属」行的副标说明「Cursor 远端用量、补录和早期历史，没有项目信息」；项目维度底部合计行右侧「全部项目 ›」进入项目页。提供商归属规则：前缀优先（`openai/`、`openai-codex/` → OpenAI，`anthropic/` → Anthropic，`deepseek/` → DeepSeek，`opencode-go/` → OpenCode-Go 单列，便于区分 opencode 内花的钱，`commandcode/`、`command-code/` → Command Code 单列，便于区分 Command Code 会员/网关内花的钱），无前缀时按模型名关键词 / app 兜底（Codex → OpenAI、Claude → Anthropic），其余归「其他」。纯展示层推导，不改动定价与存储。

  - 当前额度语义由统一 `QuotaSnapshot` 提供；紧凑入口展示主要额度，详细入口按主/次/模型专项额度展示，颜色按状态色逻辑。
  - Conversations：左侧列表按所选时间范围展示对话标题、项目、服务、模型、请求数、Tokens 与估算费用；全 Fast 对话显示 `Fast` 徽标，部分 Fast 对话显示 `Mixed`，纯 Standard 和仅未识别档位不加列表噪声。支持 Codex / Claude / Pi / OpenCode / DSH 服务筛选、单项目筛选、标题/项目搜索、最近/Tokens/费用排序和每次 200 条渐进加载；Cursor Dashboard 没有本机会话 ID，不进入本页。项目菜单区分正常（含受保护目录下未验证存在的项目）、已不存在、无明确项目和 CCBar 系统任务；为避免触发系统文件夹授权弹窗，桌面/文稿/下载/音乐/图片/影片等保护目录下的路径不做文件系统检查，仅按日志中的路径字符串归组。右侧详情固定展示该对话全部时间的四项 Token、缓存命中率、各速度档位的请求数/原始 Tokens、Fast 计费等效 Tokens、Standard/Fast 费用、四项最终费用、模型构成与完整时间信息。对话页刷新只扫描本地日志，不等待额度或服务状态网络请求。 对话页的项目身份与项目页一致（worktree 计入主仓库），从概览或项目页跳来时会清空搜索并按目标选中对话、切换到排行口径排序或按项目筛选；对话详情的模型构成按排行口径排序。

  - 本地日志读取、周期重建或统计持久化真实失败时，统计页顶部显示警告，保留仍可用的已有数据，并提供“打开设置”入口让用户触发重新计算；扫描过程中会话文件被正常归档或清理不算失败、不提示误报警告，错误恢复后警告自动消失。手动重算若被拒或保存失败，设置页重算按钮旁同步提示「保留原历史」与下一步；历史进入只读（快照由更新版本写入）或受限恢复时同样以可见提示说明当前状态。
  - 统计服务显示配置：可在「设置 → 统计服务」勾选要计入统计的服务（Codex / Claude Code / Pi / OpenCode / DSH 默认开启，Cursor 默认关闭）。关闭后该服务从侧栏过滤项、KPI 卡、Token 拆分、用量构成、高消耗对话、项目页和每日用量图表中一并消失，占比分母只统计可见服务（归一化）；全部关闭时用量构成的服务维度显示空态引导。Cursor 统计开关独立于额度卡片，但启用任一入口都会启动其只读远端刷新；本地服务关闭后仍会被扫描与入库，重新开启后历史数据照常出现。

**历史保护与恢复的行为边界**：

- 日聚合、对话档案、周期用量、扫描进度与 DSH 逐会话贡献共享同一 `snapshotID` 并同处一份快照：要么一起生效，要么一起保持原样，磁盘上不存在「新进度 + 旧汇总」这类组合。
- 升级后把旧的分散缓存一次性合成快照（只读旧文件，不修改、不删除）。旧文件缺失 = 没有这份数据；版本不受支持或损坏 = 该数据不可用并如实报告，不当作空数据继续覆盖。
- `current.json` 损坏或被截断时整体回退到 `previous.json`，绝不混合两代数据；损坏文件移入 `quarantine/` 保留证据。`current.json` 由更新版本写入时进入只读模式，只展示不覆盖。
- 主历史可用但扫描进度不可信（例如 Caches 被清理）时进入**受限恢复**：历史照常展示，进程内只做一次完整核对，通过才采纳新进度；不通过就保留历史、停止自动全量重扫，仅提示用户手动重算。
- 用户手动「重新计算用量」先在全量重扫的独立副本上生成候选，通过**完整用量向量**对账（键 = app/日/模型/速度与会话/日/模型/速度，值 = 四类 Tokens + 请求数 + 会话归组）并成功持久化后才切换；日志读取不完整、向量不一致或写盘失败一律保留原历史并如实报告，不使用「总量不减少」「键集合是超集」「逐项最大值」「新旧相加」这类弱证明。
- 源日志被删除时已保存的历史不倒扣（Claude / Codex 由无法解释的差异拒绝重算兜底，OpenCode / DSH 由逐会话贡献保留兜底）；普通增量采集不受上述任何限制影响，照常继续。
- 周期缓存里指向已被合并 / 剔除的周期记录的残留桶不算缓存失效：只丢弃这部分，能由最近窗口重建补回的自动补回，补不回的在设置页「重新计算用量」旁提示「周期用量不完整」，交给用户决定何时重算，不再为此自动全量重扫。
- 价格变化不触发自动重扫：自动扫描按当前价格计新条目，历史费用保持旧价，由用户在设置页手动全量重算——「重新计算用量」是唯一的全量重算入口（缺价补齐也只发生在这一步）；「更新价格目录」只拉取价格表，不触发重算。
- Cursor 远端计量独立于本地快照，本地恢复 / 重算不影响其桶、账号隔离与覆盖区间。

## 13. 风险 / 待持续关注

1. **非公开接口稳定性**：`wham/usage` / `oauth/usage` 字段可能随时调整，解析器需要保持容错。
2. **Keychain 弹窗**：首次读 `Claude Code-credentials` 系统会弹一次授权窗，引导文案已加。
3. **价格表漂移**：当前对齐 cc-switch / CodexBar 2026 上半年价位；模型迭代后需要同步。
4. **JSONL 量级**：长期使用后 `~/.claude/projects` 可达数百 MB；增量 watermark + seen ID 上限保证启动 / 扫描时间可控，但 seen 集合上限 20000 时若历史窗口超过该长度会有边缘重复风险。
5. **签名与公证**：发布产物走 `scripts/build.sh` 的 ad-hoc 签名，没有 Developer ID 证书也没有公证，用户首次启动需在「系统设置 → 隐私与安全性」放行一次（README 有说明）。若日后需要免放行分发，仍要补 Apple Developer 证书与公证流程。

### 历史恢复的异常边界

- 两份新快照失效或缺失时停止本地采集，保留原文件；已经使用新存储后不回读过期旧缓存。格式不兼容时要求使用兼容版本，有有效备份才展示备份。
- 对话历史或扫描进度不可信时显示可用历史并暂停采集，核对通过才恢复。日志新增或缺失导致核对失败时，不能承诺点击重算即可恢复，也不提供强制丢弃历史按钮。
- 设置页明确显示核对失败；费用重算成功但周期归属有差异时显示周期完整性未确认。DSH 贡献不可用时显示该来源暂停，其他来源继续采集。
