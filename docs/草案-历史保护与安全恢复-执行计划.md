## 1. 本轮范围与完成标准

本轮只做**历史保护与安全恢复**：保护已经采集、已经持久化的本地用量，避免缓存清理、失败重算、升级或写盘中断把它们替换为不完整数据。

包括：

1. 用量汇总、扫描进度、去重信息和 DSH 贡献作为一致的持久数据保存。
2. 保留上一份完整有效快照；加载失败时能够恢复，恢复后继续采集不重复计数。
3. 手动重算使用独立候选结果；验证和持久化成功后才替换当前结果。
4. 已有历史但缺少可用扫描状态时，保留历史并明确报告受限状态，禁止清空后盲扫。
5. 兼容导入当前版本的旧文件，保留迁移前原文件。
6. 统一覆盖普通扫描、手动重算、周期重建、DSH 恢复的写入路径。
7. 必要的状态说明、回归测试与文档同步。

不包括：项目汇总、项目映射、费用来源新功能、小时趋势、SQLite、持久化逐请求明细、永久去重库、多设备同步、预算提醒、发布与版本升级。分来源扫描只列为后续独立阶段，见第 11 节，本轮不得顺手实施。

**首版保守边界：宁可拒绝无法验证的重算，也不静默减少、叠加或伪造历史。** 这意味着某些缺失日志的历史暂时不能重算费用；这属于明确的受限结果，不能显示“全部重算成功”。

不能承诺：恢复从未采集的数据、恢复此前已被覆盖且无备份的数据、任意旧版本都能迁移、缺少全部扫描状态时仍安全继续所有来源、断电下绝对零损失。正常写盘节流仍存在未持久化窗口，不能把内存中的数据也宣称为已永久保护。

## 3. 不可破坏的约束

1. 日、对话、周期是不同投影，不相互相加。Cursor 远端缓存继续独立，不能被本地恢复覆盖。
2. 聚合数据与扫描进度必须对应同一个逻辑提交。不能保存新进度、旧汇总；也不能把新汇总与旧进度合并恢复。
3. 失败重算不得修改当前聚合器、当前扫描上下文、DSH 贡献、周期完成标记或当前有效磁盘快照。
4. 不允许把旧汇总与全量重扫相加；不允许以 `max(旧值, 新值)` 合并；不允许凭总 Tokens 不减少认定完整。
5. 费用允许因明确重算而变化，不以费用增加 / 减少判断历史是否完整。
6. 已持久化数据可恢复与普通刷新继续正常工作都要验收，不能用所有情况永久停止扫描来规避问题。
7. 无法安全继续采集的受限情况必须有明确原因与提示，不得伪装为正常完成；不能每轮重新发起昂贵全量扫描。
8. 现有 15 分钟写盘节流、无变化不写、价格目录不自动重算历史的行为应保留。
9. 不读取聊天正文到新的持久文件；不增加凭据、提示词、原始网络响应的保存或日志输出。
10. 测试只能使用临时目录与脱敏 fixture。严禁测试清理、重写用户真实 `~/Library/.../CCBar` 或 `~/.codex`、`~/.claude`、`~/.pi`、`~/.dsh`、OpenCode 数据库。

## 4. 推荐实现方案

### 4.1 一份完整提交对象，当前与上一份两级保留

首选较小范围的 JSON 方案：新增一个用量快照存储，例如 `UsageSnapshotStore`，把以下内容放在一个带独立格式版本的 envelope 中：

- 日汇总 payload。
- 对话汇总 payload。
- 周期汇总 payload 与重建完成标记。
- `ScanState`（各来源进度、解析上下文、seen）。
- DSH 贡献 payload、待复核 / 待重建状态。
- 快照 ID、创建时间，以及必要的恢复 / 兼容性元数据。

建议生产目录为 `Application Support/CCBar/usage-history/`，保存 `current.json` 与 `previous.json`。文件名允许按项目风格调整，但文档与测试必须一致。不要同时保留多套生产写入真源，也不需要新增数据库或复杂事务框架。

提交协议：

1. 串行化所有本地用量提交，准备完整候选对象，先校验结构与逻辑一致性。
2. 在后台完成编码。编码、校验失败时，当前内存和磁盘都不切换。
3. 若存在已验证有效的 current，将其原样原子保存为 previous。不能把损坏、错代或尚未提交的候选轮转成备份。
4. 原子替换 current，这是新提交的切换点。previous 写失败时终止本次提交；current 写失败时继续使用原有效提交。
5. 成功后才更新已提交状态。提交完成后的异步旧任务不得把更旧结果写回来。

每个文件本身包含完整提交，因此进程在两次文件替换之间退出，至少仍有一份完整旧提交。不要用五个不同时间的 `.bak` 拼一份恢复结果。

启动优先验证 current，失败再验证 previous；恢复 previous 后必须使用其配套进度。两个都无效时进入显式恢复受限分支，不能把失败解析等同于首次安装。

回退只能保证恢复到 previous 的提交时点。若 current 已损坏，且 previous 之后的源日志也已删除，该区间无法凭备份补回；必须显示恢复时点和可能缺失范围，不能宣称恢复了最新全部历史。候选提交失败 / 进程中断与已提交文件后来损坏是两类场景，验收和提示应区分。

要求验证：格式版本、必要字段、内部代次、字典键 / 对话关系等基本不变量；不能只检查 JSON 能否解码。可复用当前 payload，外层版本与内层数据版本区分；仅改变保存位置不能一律 bump 内层版本触发全量重建。

性能边界：整个 envelope 可能比单份 JSON 大，不能每次监听事件或无用量变化都重写整份。沿用节流、在内存暂存进度；延迟提交时快照与进度一起延迟，重启允许重读未提交增量。周期确需立即保存时也必须从匹配的完整状态组成提交，不得夹带未提交进度。记录编码、写入次数的 fixture 证据，不能只宣称“更快”。

这套方案的验收范围是写入失败和进程中断恢复；若要宣称断电耐久性，必须另行设计并验证 fsync 等保证，不能由 `.atomic` 推导。

### 4.2 旧文件迁移与异常恢复

旧路径只作为迁移输入，新存储有效后不再回头从旧文件拼状态。迁移不删除、不覆盖旧文件；日后清理另行决定。

| 输入情况 | 必须采取的行为 |
|---|---|
| 真正首次安装，没有任何旧历史 | 按现有来源规则首次采集，建立新快照 |
| 当前支持版本、主汇总与进度同代、附属数据可兼容 | 导入完整快照，核对后写入；不全量重扫 |
| 新 current 坏、previous 有效 | 整体恢复 previous，带其进度续扫，显示必要恢复信息 |
| 主日 / 对话历史可用，但没有匹配进度 | 保留并展示历史，进入恢复受限状态；禁止空状态全量结果覆盖历史或追加到历史 |
| 日与对话错代 | 各原文件保留用于恢复，不作为同一份完整历史；不能拼起来并宣称一致 |
| 周期缺失或旧标记不完整 | 保持主历史可用，明确周期待恢复；不得连带清空主日 / 对话历史 |
| DSH v1 / pending | 沿用逐会话待复核规则；源文件缺失贡献继续保留，不因存储迁移变成空贡献 |
| DSH 不可用但主历史含 DSH | 保留该分区历史，标记不能安全增量或重建；不得把空贡献归并回旧 DSH 分区 |
| 未支持的旧格式 / 更新版本格式 | 不假定兼容、不覆盖原文件；明确报告不支持；有经过验证的兼容解码器才迁移 |

加载 API 要区分“无数据”“有效”“可展示但不能安全续扫”“损坏 / 版本不支持”，避免继续使用返回空 payload 掩盖所有失败的接口做迁移决策。恢复受限状态是否单独包裹保存旧历史，可按实现选择，但不能伪造有效 `ScanState`。

首版必须支持本计划基线的格式组合，以及当前代码已经支持的 DSH v1→v2 兼容路径。更早版本如需支持，必须增加对应真实结构的脱敏 fixture 与显式迁移器，不得直接把版本号改成当前值。

若仅能显示旧历史、不能续扫，要明确这项限制。后续实现者不得通过不完整重建来“修掉提示”。本轮也不新增供用户强制丢弃历史的按钮。

### 4.3 安全重算：候选隔离与保守校验

将“收集扫描结果”“生成候选聚合”“校验”“持久化”“发布 UI”分开到必要程度，不要求大规模重构整个服务。

手动重算流程：

1. 与普通扫描、周期重建串行；完成或安全提交当前待落盘增量，取得本轮基准快照。
2. 固定本轮价格目录与周期上下文，使用独立聚合器、扫描状态和 DSH 贡献构造候选。读取期间旧结果继续展示。
3. 收集来源结果，显式区分成功完整、部分失败、来源不存在 / 不可验证。缺失旧日志不能等同于未安装来源。
4. 对候选做下述校验；无法通过则保留原结果与进度，并结束本次操作，不能陷入自动重试循环。
5. 候选持久化成功后才切换当前聚合和相关标记。失败保留基准；随后正常增量仍使用基准进度。
6. 有扫描期间新事件时，按已有排队机制安排后续普通扫描，不丢事件、不跨候选推进进度。

**首版完整性判定采用保守门槛，不凭文件数量或总量比较：**

- 任何实际读取 / 枚举 / 解码错误、来源冲突或必须重建的 DSH 未完成，均不得宣称整轮重算成功。
- 对于旧历史存在的来源，按完整键集合比较日桶 `(app, day, model, speed)` 与对话桶 `(conversationKey, day, model, speed)` 的四类 Tokens、请求数，以及会话归属和保留历史关系。金额不参与相等门槛。
- 首版优先支持**无新增写入的同一日志快照重算费用**：候选用量向量与基准相同，才允许切换新的费用。不能仅要求大于等于，也不能用一个新增会话抵消一个丢失会话。
- 候选出现新增或修正的用量向量，首版可以安全拒绝本次重算并提示“数据发生变化或覆盖无法确认，已保留原历史”；随后走正常增量。不得为通过验收临时放宽比较。活动日志下拒绝重算是已知限制，应在交付中说明。
- 对具有日汇总补录、旧 DSH 待复核贡献等混合历史的情况，保留其原有来源语义；无法准确对账则拒绝替换。不得把补录金额重新拆成虚构事件。
- 周期是独立派生投影：固定相同周期 / 账号区段上下文时核对桶键、质量、用量；若上下文变化，不把缺少周期归属误判为完整，也不为使周期相等而丢主历史。受限周期重建仍按已有窗口和成功来源规则独立处理。

以上相等校验只保证本轮已保存的统计维度没有变化，不宣称证明了每个原始事件身份。它也不能承担修复过去错误 Tokens 的任务；需要改变历史用量口径的迁移，必须另行定义有证据的替换规则。

特别是同一完整聚合键下，删除旧事件又追加用量完全相同的新事件，当前聚合信息可能无法区分。首版不承诺检测这种事件级替换；如必须覆盖，需要新增来源完整性证据或持久化事件身份，应另行评估范围，不能让模型通过伪造测试掩盖限制。

`forceRescan` 中缺价刷新后的第二轮也必须通过同样的候选校验，不能保留“第二轮先清空”的绕过路径。第一轮已提交而第二轮失败时，应保留第一轮有效结果，并明确说明最终状态。

### 4.4 错误与 UI

优先复用统计页现有警告、设置页现有重算行和进度，不新增复杂恢复管理页面。

内部结果应能区分：成功、保留旧历史的拒绝重算、提交失败、恢复上一份、恢复受限。不要只依赖字符串前缀区分业务状态。

必要提示应表达：发生什么、旧数据是否保留、当前能否继续采集。提供中英两种文案，沿用 `tr`。不要在“无法从日志恢复”时仍提示“点重新计算补齐”，也不要按钮转圈结束就暗示成功。

日志只输出脱敏原因、来源、数量、版本和提交状态，不输出原始日志正文或完整敏感路径。

## 5. 按顺序实施，每批保持可审阅

| 批次 | 工作 | 批次出口 |
|---|---|---|
| H0：盘点 | 复核所有读写入口、版本、状态与已有改动；记录实现基线 | 给出真实影响文件，不改无关代码 |
| H1：存储 | 新 envelope、目录注入、串行提交、current / previous、结构校验与故障注入 | 能用临时目录独立证明提交和恢复协议 |
| H2：迁移 | 旧文件读取结论、当前版本导入、DSH pending、异常状态 | 成功导入等价、重复导入幂等、失败不破坏原文件 |
| H3：常规路径 | bootstrap、普通扫描、周期单独写入接入同一存储；保留节流 | 普通新增只入账一次；失败后重启仍可继续 |
| H4：安全重算 | 候选隔离、结构化结果、完整性对账、二次缺价扫描 | 成功替换与各种拒绝路径均不损伤旧历史 |
| H5：交付 | 必要 UI 文案、项目文件、文档、测试证据 | 按第 8 节给出完成情况与限制 |

不要在 H1 只写辅助类后就宣布完成；必须接入所有生产写入路径。不要留下新存储只用于测试、实际运行仍写旧文件的情况。

建议新增文件数量保持克制：存储服务、迁移 / 校验辅助类型、对应测试即可，具体命名可遵循现有风格。不修改定价表、源日志解析口径或 Provider 配置。

## 6. 必须增加的自动化验收

测试类建议命名为 `UsageSnapshotStoreTests`、`UsageHistoryRecoveryTests`、`UsageSafeRebuildTests`，也可以合理合并。测试必须走实际生产存储 / 协调逻辑，通过依赖注入控制目录、扫描结果、价格、时钟与失败点；不能在测试中重新实现一套算法来证明自身。

| 编号 | 场景与操作 | 必须断言 |

| A01 | 当前版本旧日 / 对话 / 周期 / 状态 / DSH 同代导入 | 各完整键集合、Tokens、请求、Decimal 费用、档案及进度与旧数据一致；不重扫 |
| A02 | 同样旧文件再次启动迁移 | 使用新快照，不重复累计、不重复迁移；旧文件字节保持不变 |
| A03 | 迁移编码失败、备份失败、current 替换失败 | 旧文件未改，原可用快照不变，重试成功后只提交一次 |

| A13 | 同一会话同一天缺部分日志；新增数据位于不同完整桶键或导致分项向量不等 | 拒绝替换，不能用总量相抵或逐桶最大值合并；同键同向量事件替换的不可辨识限制另行记录 |
| A14 | 全量候选部分来源读取失败 / 解码失败 / DSH 冲突 | 不提交部分候选，当前各来源及错误状态正确；失败来源明确 |
| A15 | 候选生成后持久化失败 | 内存 UI、旧进度、DSH、周期标记与原提交一致；下一次普通扫描不重复 |
| A16 | 缺价刷新触发第二轮候选，第二轮失败 | 第一份仍有效；没有二次清空路径，不显示完整成功 |
| A17 | DSH v1 pending、已删除会话、换 generation、父子归并 | 旧贡献保留、待复核标记正确、不翻倍；沿用现有统计语义 |
| A18 | OpenCode 会话更新、删除、库暂时不可读 | 替换更新贡献、保留删除历史、错误不清零；不将全会话当增量相加 |
| A19 | 周期重建单独保存、保存失败、与普通扫描交错 | 日 / 对话与进度保持一致，失败不提前更新周期完成标记；新实例恢复可对账 |
| A20 | 一次性历史补录与重算 | 补录历史不丢、不加两次；无法对账时明确拒绝，不虚构明细 |
| A21 | 相同快照重复扫、正常追加、提交失败再重试、重启续扫 | 每条新增只计一次；按完整键检查金额和 Tokens，不能只看条目数 |
| A22 | 并发手动重算 / 普通刷新 / 周期请求，扫描期间继续追加 | 按顺序处理；旧任务不能覆盖新提交；新事件最终被处理 |
| A23 | 未到写盘窗口，先增量、再无变化、再重启 | 持久化进度不领先汇总，续扫结果不丢不重；无变化不高频重写大快照 |
| A24 | Cursor 已有远端历史，执行本地重算 / 恢复 | Cursor 桶、账号隔离、覆盖范围不受影响 |
| A25 | 重算期间日志继续变化导致向量不等 | 保留基准并报告受限；普通增量能继续，日志静止后可成功重算（2026-10-08 起：手动重算以当时的日志为准直接提交，普通增量从新进度继续，重复重算幂等） |

A07 至少覆盖：候选编码前后、previous 更新前后、current 切换前后、切换成功但内存尚未发布。仅在函数抛异常后看当前对象不够，必须重新创建存储 / 服务验证重启行为。

数值对账必须保留 Decimal 精度与各 Token 分项；比较完整键集合，不能只比较格式化后美元字符串。周期完成标记、DSH 待复核状态、缺价标记也属于断言范围。

## 9. 独立验收者执行顺序与阻断标准

独立验收必须先看真实最终 diff，不能只读 DeepSeek 总结或验证记录。默认只读，不自动修复。

1. 读 `AGENTS.md`、本计划、验证记录；检查 git 当前状态、分支与最近提交。
2. 若实施改动未提交，用 `git diff HEAD` 覆盖 staged + unstaged，另读 untracked 文件。若已提交，以实际实施起点到当前 HEAD 的 diff，加未提交改动；不要只审最后一个 commit。
3. 核对所有生产加载、保存、清空、重算、周期与 DSH 路径，确认不存在旧路径绕过。
4. 逐项检查 A01～A25 的断言是否真正覆盖生产逻辑；关注重启、状态配套、费用与用量分离。
5. 获得授权后运行最小必要构建与测试；静态推断、自动化结果和 UI 手动验收分别报告。
6. 按 P0/P1/P2 给出具体文件 / 行号、触发、影响和证据；最后给出“可合入 / 有阻断 / 验证不足”。

以下任一项为验收阻断：

- 仍能因 scan-state 缺失、候选失败或版本变化先清空唯一有效历史。
- 单份文件备份被当成一致快照，或者恢复后进度与聚合不同步。
- 所谓“重算成功”只判断无异常、返回 Bool、总 Tokens 不减少或文件数相同。
- 新旧相加、逐项最大值、候选提前修改线上聚合、第二轮重算绕过校验。
- 普通扫描失败后重试重复计数，或者完整状态下普通新增也被永久阻断。
- 周期独立写入或 DSH 贡献旁路破坏一致性；Cursor 被本地操作清空。
- 测试触碰用户真实数据；测试未加入 target；测试只有辅助类型无真实调用链覆盖。
- 将未运行、跳过或仅编译通过写成故障恢复验证通过。

## 11. 后续独立阶段：分来源扫描（本轮不实施）

历史保护完成并验收后再另行授权。该阶段保持统计口径与存储格式不变：

- `UsageLogWatcher` 从全局 Bool 改为来源集合，回调能根据已监听根与事件路径判断来源；无法可靠归属、监听失败或需要全量核对时放行相应全量检查。
- `UsageService` 接收扫描计划，只启动选中的本地来源；被跳过来源不能用空 Result 替换其状态。
- 保留 30 分钟兜底、新目录发现、扫描期间事件、失败来源重试、手动刷新和重算语义。
- 将来源错误与本轮状态正确保留，不能因本轮未扫就清掉此前未恢复的错误。
- 当前显示开关只影响展示，不能顺手改为停止历史采集；Cursor 不属于本地五来源扫描计划。

独立验收：

| 编号 | 操作 | 预期 |
|---|---|---|
| S01 | 只追加 Codex | Codex 扫描器调用一次，其余正常来源零次；最终结果等价 |
| S02 | 多来源追加 | 只启动变化来源，不漏任何一项 |
| S03 | 扫描时再次变化 | 下一轮仍能消费事件 |
| S04 | 来源失败但没有新文件事件 | 失败来源仍有重试机制 |
| S05 | 无变化超过兜底间隔 | 执行完整核对 |
| S06 | 首次出现目录、根移动、监听建立失败 / 事件不可归属 | 安全兜底，不永久停更 |
| S07 | 跳过来源后保存、重启 | 原进度、seen、贡献、日 / 对话 / 周期数据完整保留 |
| S08 | 手动刷新、强制重算 | 与阶段开始前约定语义一致，不被脏标记误跳过 |
| S09 | 同一 fixture 分来源扫与全来源扫 | 完整键集和用量 / 费用一致；另比较扫描器调用次数 |

结构性减少调用可由注入计数验证；CPU、磁盘读写和功耗收益只有同机同数据实测后才能报告。不要把“少启动四个扫描器”直接换算成某个省电百分比。
