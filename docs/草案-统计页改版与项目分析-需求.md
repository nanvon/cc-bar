# 统计页改版与项目分析 · 需求草案

> 状态：**已评审、未实施**（2026-09-28 产品讨论定稿）。前置的「历史保护与安全恢复」「性能与功耗等价优化」已合入。技术方案：[草案-统计页改版与项目分析-技术方案.md](草案-统计页改版与项目分析-技术方案.md)。
>
> 设计稿：[统计页改版画布](https://claude.ai/artifact/6LEPmP6DbN51ZbMNCokM8H)（私有链接）。画布中的数字都是示例数据；画布里非服务维度用的是蓝色，以本文 §6.3 的紫色为准。
>
> 与 [草案-CCBar2.0-设计方案.md](历史参考/草案-CCBar2.0-设计方案.md) 第二节的关系：项目页形态沿用其思路，但**不采用**其中「展示项目 / 映射关系 / 合并建议 / 导出」的设计，项目归属以本文 §4.2 为准。

## 1. 目标与范围

统计页只做「看」，不做「改」。本次解决三个问题：

1. 概览信息分散在按服务、按模型、按提供商三个面板里，一屏看不完。
2. 用户无法回答「这个月的用量花在了哪个项目上」。
3. 周期（Cycles）和额度时间线（Timeline）是同一类信息，却分在两个视图里。

范围：

| 部分 | 内容 |
|---|---|
| 侧栏视图 | `概览 / 对话 / 项目 / 额度` 四项；原 Timeline 与 Cycles 合并为「额度」 |
| 概览改版 | 三个构成面板合并为一个可切换维度的「用量构成」；新增「高消耗对话」 |
| 项目页（新增） | 项目列表 + 详情，含分支、worktree、高消耗对话、未归属说明 |
| 额度页 | 周期卡与时间线同屏；周期进度条按项目拆分（估算） |

不做：订阅价值展示、套餐价格表、分享卡片、用量节奏预测、按小时热力图、预算提醒、自动合并建议、手动合并 / 拆分项目、项目数据导出。

## 2. 侧栏与全局

| 视图 | EN / CN | SF Symbol |
|---|---|---|
| 概览 | `Overview / 概览` | `rectangle.split.2x2` |
| 对话 | `Conversations / 对话` | `bubble.left.and.bubble.right` |
| 项目 | `Projects / 项目` | `folder` |
| 额度 | `Quota / 额度` | `gauge.with.needle` |

- 概览、对话、项目三个视图共享同一对「粒度 + 时间范围」状态，切换视图不丢失选择。项目页使用与对话页相同的两个 `.menu` Picker。
- 服务筛选：项目视图下选中 Cursor 时回退到「全部」，规则与对话页一致（Cursor 没有本机对话，无法归属到项目）。额度页整页随服务筛选变化：选 Codex 或 Claude Code 时只显示对应的周期卡和时间线；选 Cursor、Pi、OpenCode、DSH 时显示「暂无额度数据」空态。
- 金额统一称为「API 等值」（`API equivalent`），替换概览 KPI 中的「总花费」。它表示按 API 价格估算的金额，对订阅用户只作参考。

## 3. 概览

在默认窗口尺寸（1600×1100）下一屏看完，不需要滚动。窗口高度不够时由外层滚动。

模块顺序：

1. **KPI 行**：`总 Tokens`、`API 等值`，再加各可见服务卡，保持现有 delta 规则。
2. **每日用量 + Token 拆分**：两者并排，每日用量约占 2/3 宽度。柱宽沿用现有按样本数分档的规则（30 根为 10pt），不随面板宽度拉伸。Token 拆分沿用现有紧凑版，Fast 行规则不变。
3. **用量构成 + 高消耗对话**：两者并排，用量构成约占 5/9 宽度。

### 3.1 用量构成

替代原来的 By service、By provider、By model 三个面板。

- 面板标题右侧放维度分段控件：`服务 / 提供商 / 模型 / 项目`，默认显示「服务」。切换维度只影响本面板。
- 顶部是一条 6pt 高的占比条，按行依次拼接，段间留 2pt 间隔。下方用一行小字注明合计 Tokens 和 API 等值。
- 列表列：8pt 色块、名称与副标、占比、Tokens、API 等值。按 API 等值降序排列，「其余 / 其他 / 未归属」固定排在最后。
- 行数上限：服务维度全部列出；提供商维度取前 3，其余合并为「其他」；模型维度取前 5，其余合并为「其余 N 个模型」；项目维度取前 4，其余合并为「其余 N 个项目」，另加一行「未归属」。
- 悬停一行时显示该行的 Token 拆分（输入、输出、缓存命中、命中率）；有 Fast 用量时追加 Fast 明细。原来三个面板逐行展示的拆分信息改由悬停提供，内容不减少。
- 点击行为：
  - 服务：把侧栏服务筛选切换到该服务。
  - 提供商：就地展开该提供商下的模型，沿用现有 By provider 的展开行为。
  - 模型：无点击行为。
  - 项目：跳转到项目页并选中该项目。
  - 未归属：跳转到项目页的未归属详情。
- 原 By provider 面板的排序 Picker 取消，排序统一按 API 等值。
- 选中「项目」维度时，面板底部显示一行说明：`未归属：Cursor 远端用量和补录数据没有项目信息`，右侧是「全部项目 ›」入口。

### 3.2 高消耗对话

- 按 API 等值取范围内前 5 个对话。标题旁注明「前 5 个占 API 等值 X%」。
- 每行依次为：序号、服务小色块（10pt）、标题、`项目 · 分支 · 日期`、金额条、API 等值、`Tokens · 占比`。金额条长度按第一名归一，用中性灰。
- 点击行跳转到对话页并选中该对话；「全部对话 ›」跳转到对话页，排序切为「费用」。

## 4. 项目页

### 4.1 布局

左侧是项目列表（宽约 400pt），右侧是详情，结构与对话页相同。

**列表**

- 顶部：搜索框（匹配项目名或路径）、粒度 + 范围菜单、项目数、排序菜单。排序可选 API 等值 / Tokens / 最近活跃，默认按 API 等值。
- 每行：项目名、徽标、路径尾段、API 等值、`Tokens · 最近活跃`，以及一条工具构成细条。细条按服务色分段，宽度按该项目占第一名的比例缩放。
- 徽标：`含 N 个 worktree`、`已不存在`、`非 Git 目录`。
- 特殊行固定排在列表末尾，名称用次级色：`无明确项目`（从主目录或临时目录启动的对话），以及有数据时显示的 `CCBar 系统任务`。
- 列表底部固定一行「未归属」，显示 Tokens 和 API 等值，并附一句原因。点击进入未归属详情。

**详情**（默认显示所选范围）

1. 标题行：项目名、Git 徽标、完整路径、「在访达中显示」按钮。
2. KPI：Tokens、API 等值（这两项带 delta）、对话数、活跃天数（`21 / 30`）。
3. 全部时间一行：`以上为近 30 天。全部时间：X Tokens · $Y · 首次使用 日期`。
4. 每日用量（按服务堆叠）和「工具与模型」并排。「工具与模型」包括服务占比条和模型列表。
5. 分支表（分支、对话数、Tokens、API 等值）和「高消耗对话」并排。高消耗对话取前 3，「在对话页查看 ›」跳转到对话页，并按该项目筛选。
6. 仓库与 worktree：只在项目含 worktree 时显示，只读，列出主仓库和每个 worktree 的路径、对应分支和用量。

### 4.2 项目归属规则

- 项目身份取规范化后的仓库根路径，与现有对话页的项目口径一致。
- **worktree 自动计入所属主仓库**，不需要用户操作。worktree 在详情页的「仓库与 worktree」和分支表中分别列出。
- 读不到 worktree 的主仓库信息时，按独立项目显示。受保护目录的处理沿用现有策略，不会为了判断归属而触发系统授权。
- 其他多路径情况（同一仓库克隆到两处、目录搬家等）按不同项目显示，不做合并，也不提供合并建议。
- Cursor 远端用量和补录的按天汇总数据没有项目信息，计入「未归属」，不分摊到任何项目。
- 统计页只读：不提供合并、拆分、重命名、隐藏项目等编辑操作。

### 4.3 未归属详情

- 标题「未归属」，附徽标「不属于任何项目」和一句说明：这些用量计入概览总量，但不出现在任何项目里。
- KPI：Tokens、API 等值、占概览总额的比例。
- 来源分两行，各自显示金额与原因：
  - Cursor 远端用量：Cursor 只提供账号级计量。附「在概览中筛选 Cursor ›」入口。
  - 补录的历史数据：只有按天汇总的数据。注明日期区间和服务。
- 每日用量图：Cursor 用服务色，补录部分用灰色斜纹。

### 4.4 状态

| 状态 | 表现 |
|---|---|
| 首次整理（无缓存） | 列表区显示「正在整理历史对话」、进度条和已处理的会话文件数，下方为占位行 |
| 再次扫描 | 保留旧内容，顶部显示扫描指示，规则与对话页一致 |
| 范围内没有项目 | 列表区居中显示：文件夹图标、`今天还没有项目用量`、数据来源说明，以及「查看近 30 天」按钮；底部「未归属」照常显示；详情区只显示一行次级文字 |
| 项目路径已不存在 | 列表徽标显示「已不存在」，历史数据照常展示 |

## 5. 额度页

在默认窗口尺寸下一屏看完。账号超过两个时，时间线换行显示，页面滚动。

1. 标题：`额度` 加一句副标。
2. **当前周期**：4 张卡并排一行，顺序为 Codex 5 小时、Codex 周、Claude 5 小时、Claude 周。每张卡包含：
   - 标签行和可信度标签，沿用现有规则。
   - 「用满预估」，Tokens · 费用。
   - `已用 X · $Y`，右侧是 `官方 N%`。
   - 按项目分段的进度条（§6.1）。
   - 图例：前 2 个项目，其余合并为「其他」。
   - 重置倒计时。

   空态沿用现有的定向空态。
3. **今天的额度变化**：右侧是全局 `5H / 本周` 切换。账号分区两列并排，每个分区包含：
   - header 与 metric，沿用现有规则。
   - 折线图，图上加「窗口重置」和「现在」两条竖向参考线。
   - 「变动明细 · N 条」折叠按钮，默认收起；展开后显示现有表格。

   5H / 本周的区间规则、折线分段和点的颜色都沿用现有 Timeline。

周期进度条的项目估算：

```
项目占用 ≈ 该项目在本周期的 API 等值 ÷ 该服务本周期 API 等值合计 × 官方已用比例
```

- 只用本机能归属到项目的用量。无明确项目、系统任务和其他项目并入「其他」。
- 分区标题旁固定注明「按项目拆分为估算」，悬停分段时显示项目名、估算比例和本周期 Tokens。
- 本周期没有本机用量、但官方已用比例大于 0（例如在其他设备上使用）时，整段显示为「其他」。

## 6. 视觉规则（本次确定）

### 6.1 额度进度条按项目分段：允许，作为限定例外

- 只适用于额度页的周期卡，Popover、悬浮窗、菜单栏的额度条仍按现有规则用状态色。
- 已用部分按项目分段，配色见 §6.3；未用部分是轨道底色。
- 剩余状态改由 `官方 N%` 数字表达：剩余 ≥20% 用 primary，<20% 用 low 橙，=0 用 empty 红，统一走 `statusColor`。
- 理由：这张卡的主角是「用了多少、用在哪」，剩余状态由 Popover 负责。项目拆分放进进度条，额度页可以省掉一个独立面板，一屏看完。

### 6.2 KPI 服务卡主数字改用中性色

- 概览 KPI 服务卡的主值改用 primary，识别色只留在标签前的 12pt tile 上。项目页 KPI 同样处理。
- 理由：服务识别色只用于 tile、logo 这类识别元素，不再铺在大号数字上。桃橙色放大到 22pt 后观感差，多张卡并排时整行颜色太杂。
- 落地时需要同步修改 [设计风格.md](设计风格.md) §4.2「用在哪」和 [界面布局.md](界面布局.md) §3.4.1 中「主值服务卡用服务色」的描述。

### 6.3 非服务维度使用紫色顺序色阶

提供商、模型、项目三个维度没有识别色，统一按排名套用一组紫色色阶（第 1 名最深）。另有两个固定配色：「其他 / 其余」用中性灰，「未归属」用灰色斜纹。

| 角色 | 浅色 | 深色 |
|---|---|---|
| 第 1 名 | `#3F3A8F` | `#B3ADF2` |
| 第 2 名 | `#5E56C2` | `#8F87E6` |
| 第 3 名 | `#8C85D9` | `#6C63CC` |
| 第 4 名 | `#BDB8EC` | `#4D469E` |
| 其他 / 其余 | `#C7C7CC` | `#48484A` |
| 未归属 | `#C7C7CC` 与底色 135° 斜纹，间距 3pt | `#636366` 与底色斜纹 |

- 不用蓝色：Antigravity、Pi、DSH 的识别色和系统 Accent 都是蓝色，同屏容易混淆。不用灰色：会与 Codex 的石墨灰、Cursor 的近黑混淆。
- 色阶只表示排名，不表示身份。同一项目在不同卡片里可能是不同深浅，所以必须同时显示图例或名称。
- 服务维度继续用服务识别色。

### 6.4 配套约定

- 大面积的服务色只出现在堆叠柱图里，其他位置只用小色块（≤12pt）。
- 占比条高 6pt，行首色块 8pt，高消耗对话的金额条用中性灰 `#AEAEB2`。
- 数字字号：KPI 主值 22pt；面板内的次要数字（Token 拆分等）13–13.5pt。
- 深色模式与窄窗口不单独出稿：颜色全部走系统语义色和上表的深色值。宽度沿用 `StatsView.wideCanvasWidth` 断点，窄于断点时并排的两块改为上下排列。

## 7. 验收

| 编号 | 操作 | 预期 |
|---|---|---|
| P01 | 默认窗口打开概览 | 四块内容无需滚动即可看完 |
| P02 | 构成面板切换四个维度 | 行数上限、排序、合并行、配色符合 §3.1 和 §6.3；占比合计 100% |
| P03 | 项目维度的各行合计 | 各项目 + 其余 + 未归属 = 概览总 Tokens / API 等值 |
| P04 | 悬停构成行 | 显示该行的 Token 拆分；有 Fast 用量时显示 Fast 明细 |
| P05 | 点击高消耗对话、构成里的项目行 | 分别跳转到对话页选中对话、项目页选中项目 |
| P06 | 在 worktree 中使用 Claude Code 或 Codex | 用量计入主仓库；详情的「仓库与 worktree」和分支表能看到该 worktree |
| P07 | worktree 主仓库信息不可读、位于受保护目录 | 按独立项目显示，不弹系统授权 |
| P08 | 选中项目，切换时间范围 | 详情数字随范围变化，「全部时间」一行不变 |
| P09 | 项目视图下选 Cursor | 服务筛选回退到「全部」 |
| P10 | 未归属详情 | 两类来源的金额之和等于未归属合计 |

| P12 | 额度页默认窗口 | 周期卡与两个账号的时间线无需滚动即可看完 |
| P13 | 周期进度条 | 各分段之和等于官方已用比例；剩余 <20% 时 `官方 N%` 变为橙色 |

| P15 | 深色模式 | 紫色色阶、斜纹、状态色均使用深色值，文字对比度不低于 4.5:1 |

## 8. 分期

每期都能单独发版：

1. **概览改版与侧栏视图调整**（含 §6.2、§6.3、§6.4）。
2. **项目页**：包括 worktree 归属、未归属详情和各种状态。
3. **额度页合并**：包括 §6.1 按项目分段。

每期落地时，把有效内容并入 [产品需求.md](产品需求.md)、[界面布局.md](界面布局.md)、[设计风格.md](设计风格.md)，并在本文头部标注实施状态。
