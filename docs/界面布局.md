| 项 | 值 |

### 1.3 Header

- **容器**:HStack(spacing 4),padding `14pt 上 / 12pt 左右 / 12pt 下`(到 separator)。
- **左侧**(VStack,line-height 1.1):
  - `Usage` — 13pt .semibold
  - `用量 · refreshed 32s ago` — 11pt secondary
    - 正常时 `refreshed {n}s ago` / `{n}m ago` / `{n}h ago`,取所有已启用主 Provider 中**最近**一次成功时间。
    - 任一已启用 Provider 的 `lastError` 非空(= 最近一次尝试没成功,成功会由 `storeXxx` 清空它)时改为 `refresh failed · data from {age} ago` / `刷新失败 · {age} 前的数据`——必须说出正在失败,否则断网时 header 报"刚刷新过"、下面每个服务却挂着报错。从未成功过则只显示 `refresh failed · 刷新失败`,两者都没有时 `waiting… · 等待数据`。
    - 正在失败的服务**全部**是网络类失败(`QuotaRefreshState.lastErrorIsNetwork`)时进一步说成 `network unavailable · 网络不可用`。网络不可用是全局事实,归 header;凭据过期一类是单个服务的事实,留在各自 block——断网时 header 说"网络不可用"、Claude 块说"凭据已过期",两条各自成立,不必把网络状态耦合进每个 Provider 的错误文案。判定要求"全部",只要有一个服务败在别的原因上(比如 401)就说明网络是通的。
    - 由 `TimelineView(.periodic(by: 1))` 每秒重算,Popover 不可见时不调度。
- **右侧**(HStack,spacing 4):
  1. **status dot** — 7pt 圆点(live/stale/offline),颜色按 设计风格 §4.3。判定同时看数据新鲜度与"当前是否在失败":有 `lastError` 时不给绿灯,数据仍新(≤ 3× 刷新间隔)为 stale、更旧为 offline;无错误时按 age 走 1.5× / 3× 两档。失败态 tooltip 为 `Refresh failing — showing the last data that came through · 刷新失败,显示的是上次成功取到的数据`,全部败在网络上时换成 `Network unavailable — … · 网络不可用,…`,正常态仍是 `Live · 在线` 等。
  2. **Refresh** — `arrow.clockwise` 13pt,按钮 `26pt × 22pt` 圆角 5pt,hover 浅灰背景(`Color.primary.opacity(0.08)`)+ 手型光标。点击触发 `appState.refreshNow()`,图标旋转 360° / 700ms ease-in-out。**不禁用**:`AppState.refreshNow()` 内部已做 in-flight 去重,不会重复发请求,刷新开始后由 `isRefreshing` 驱动转圈。
  3. **Open Statistics** — `chart.bar.xaxis` 13pt,同尺寸按钮。点击先设 `appState.mainTab = .stats` 再 `openWindow(id: "main")`,Popover 关闭。
  4. **Settings** — `gearshape` 13pt,同尺寸按钮。点击先设 `appState.mainTab = .settings` 再打开主窗口,与 ⌘, 命令行为一致,总是落到设置 tab。
  5. **Quit** — `power` 13pt,同尺寸。点击 `NSApp.terminate(nil)`,hover tooltip `Quit · 退出`。

> 设计依据:用户反馈一级操作(设置 / 刷新 / 统计 / 退出)藏在 kebab + footer 里不直观,统一拉到顶部图标行,降低点击层级。Quit 早期收在 `ellipsis` 菜单需要点两次,后续也拉平为一级图标。

- **separator**:0.5pt 全宽,`.separatorColor`。

### 1.4 服务 block（主 Provider 共用结构）

整个 block 用 `14pt 上下 / 16pt 左右` padding。

#### 1.4.1 Service header row(HStack,gap 9pt)

| 元素 | 规格 |
|---|---|
| 服务 tile | 22pt × 22pt squircle(6pt 圆角),服务识别色填充,白色 logo 14pt 居中。详见 设计风格 §11.2。 |
| 服务名 + plan(HStack firstTextBaseline,spacing 8) | `Codex` 13pt .semibold kerning -0.1(不截断)<br>`OpenAI · Plus` 11pt secondary,宽度不够时只截断这一段(按 `email · plan` 拼接,隐私模式将 email 替换为「账号 NN」,无账号和套餐时兜底品牌名) |
| Spacer | — |
| 服务状态圆点 | 6pt 圆,贴 Spacer 后,行尾。颜色按 statuspage indicator(none 绿 / minor 黄 / major 橙 / critical 红 / maintenance 蓝 / unknown 灰),未拉到过任何状态时不显示。受设置项 `showServiceStatus` 控制。三家 statuspage 同时抓失败(`AppState.serviceStatusUnreachable`,= 本机出不去网)时降级为灰点 `unknown`,tooltip `服务状态获取失败 · 上次成功在 {age} 前`——保留下来的旧快照不能再当成"服务正常"展示。tooltip 的时间一律用 `fetchedAt`(本机上次成功拉取时刻),不用 statuspage 自己的 `updated_at`,后者断网时根本不动。 |

#### 1.4.2 Body row(HStack,alignment center,gap 10pt,marginTop 12pt)

**左栏:主要额度大数字 + 动态窗口标签**(VStack,center,spacing 4,width 72pt)

- 第一行:HStack(firstTextBaseline,spacing 0),`42` 32pt .semibold monospacedDigit kerning -0.8 + `%` 16pt .semibold(状态色;无快照时 `.secondary` 显示 `--`)。
- 第二行:固定短标签,不随 App 语言切换,9pt .semibold kerning 0.5 .tertiary:五小时额度统一显示 `5HOUR`;周额度 Codex 显示 `WEEKLY`、Claude 统一显示 `ALL`;Antigravity 主条/副条带官方组名(`displayName` 驱动):主条 `GEMINI 5H`、副条 `GEMINI WK`,辅助行 `CLAUDE 5H` / `CLAUDE WK`;`modelWeekly` / `unknown` 显示模型名(空则 `MODEL` / `CURRENT`)。
- 宽度固定为 72pt 居中对齐，与次要额度行标签严格等宽，确保所有卡片主/次进度条左端点垂直重合。
- 状态色规则按 设计风格 §4.3。

**右栏:进度条 + reset / 费用两行**(VStack,leading,spacing 8,flex 1)

1. **ProgressBar**:高 7pt(圆角 3.5pt),状态色填充 + `.quaternarySystemFill` 轨道。进度 = `primaryWindow.remainingPercent / 100`。
2. **文本行 1**(HStack,spacing 0):
   - 左:`ResetTimeText` 紧凑格式 `2h18m`(11pt .medium primary),悬停行内切换相反格式(剩余时长 ↔ 具体时刻,当天 `HH:mm`,跨天 `MM-dd HH:mm`);无重置时间显示 `—`。
   - 右:`today · 今日` 与 `this week · 本周` 两项费用,`$12` 11pt .medium primary monospacedDigit(取整美元,`<$1` 用于 0 ~ 0.99)+ 10pt tertiary 标签,HStack spacing 10。Codex / Claude 取本机日志聚合，Cursor 汇总已成功拉取的远端计量数据；有缓存缺口时后台补拉并保留当前金额，仅完全没有远端快照时显示 `—`。
3. **文本行 2**(HStack,spacing 0):
   - 左:`reset · 重置` 9.5pt tertiary。
   - 右:`cost · 费用` 9.5pt tertiary。

**Cursor 特例**：主额度固定使用 `cursor-total` 并显示标签 `TOTAL`；`cursor-auto` 与 `cursor-api` 作为缩小额度行显示 `AUTO` / `API`，不映射为 Weekly。今日 / 本周费用复用既有位置与样式，仅数据来源改为远端计量。`isUnlimited == true` 时左栏值位显示 `∞`（与 Codex / Claude 的「数值 + 窗口标签」同构），标签固定 `UNLIMITED`，右栏不渲染进度条、只保留重置时间与费用行；同一个意思不重复第二遍。

#### 1.4.3 次要额度行（compactLimitRow，HStack, gap 10pt）

- **左侧标签**：9pt .semibold kerning 0.6 .tertiary，宽度固定 72pt（`.leading` 对齐），与主行左栏对齐。
- **中部进度条**：`ProgressBar` 高 2.5pt（圆角 1.25pt），自适应吃满剩余宽度。
- **右侧百分比**：10.5pt .medium monospacedDigit，宽度固定 32pt（`.trailing` 对齐）。
- **右侧重置时间/状态**：10.5pt tertiary，宽度固定 68pt（`.trailing` 对齐），保证不同字符长度（如 `6d1h` vs `5d23h` vs `尚未使用`）下细进度条右端点完全平齐；68pt 放得下悬停或「具体时间」设置下的跨天格式 `MM-dd HH:mm`（约 61pt）。
- **Other Codex Accounts 行**沿用同一套尺寸：左侧名称列宽 72pt（名称 12pt + 副标题 10pt；副标题有别名时为 `email · 套餐`，无别名或无 email 时只显示套餐），标签 9pt .semibold tertiary（宽 18pt）、进度条高 2.5pt、百分比 10.5pt .medium（宽 30pt）、重置时间 10.5pt tertiary（宽 70pt）。

#### 1.4.4 Block 间分隔

- 相邻 Provider 之间:0.5pt 横线,**左右各 inset 16pt**。
- 最后一个 block 之后无 footer,由系统 `NSPopover` 圆角承接底边。

#### 1.4.5 空状态 / 错误状态

- `snapshot == nil` 且 `error == nil`:左栏显示 `--` 32pt `.secondary`,右栏进度条空轨道 + reset 显示 `—`,无额外文案。
- `error != nil`:block 底部追加一行,`Color.orange` + 前置 `exclamationmark.triangle.fill` 图标(10pt),lineLimit 2。左栏按最后一次成功快照继续显示(`appState` 不清空快照)。
  - 文案统一来自 `QuotaError.userMessage`(双语、一句话、不含技术细节),**所有 Provider 一视同仁**,不再把 Cursor / Command Code 抹成通用的"刷新失败"——那样断网时它们只会说"刷新失败",看不出是网络问题还是账号问题。`QuotaError.description` 仍是技术串,只进日志。
  - 文案一律写用户视角的话,不出现「令牌」「限流」「响应格式」「TLS 握手」这类实现词。网络类失败按 `NetworkFailureKind` 分档:`网络未连接` / `连不上服务,请检查网络或代理` / `连接超时,请检查网络或代理` / `安全连接失败,请检查代理设置`。HTTP 失败的响应体若是 HTML 而非 JSON(`looksLikeInterceptedResponse`),说明请求被代理拦截,文案为 `被网络代理拦截,请检查代理设置`,且不据此判定账号失效;其余按档位给 `请求过于频繁,请稍后再试` / `登录已失效,请重新登录` / `服务暂时不可用,请稍后再试`。
  - **状态码只在兜底的未知档露出**(`获取失败(HTTP {code})`)——那时它是唯一线索;401 / 429 / 5xx 这些常见档对用户没有信息量,完整的 `http {code}: {body}` 本来就在 `description` 与日志里。
  - 其他账号行的错误态样式相同。
- 服务在 Settings 里被关闭(`showXxx == false`):**整个 block 不渲染**。
- 全部服务关闭:Popover 只显示 header + 中部两行占位 `No services enabled · 未启用任何服务`(12pt .medium secondary)+ `Enable a service in Settings → Services & Accounts · 到「设置 → 服务与账号」开启`(11pt tertiary),垂直 padding 24。

### 1.5 Footer(已废弃)

> 原方案的 footer(左侧 `Open Statistics` 按钮 + 右侧 refresh + kebab)已**完全移除**。所有一级操作上移到 §1.3 Header 的图标行,刷新进度通过 header 刷新图标自身旋转 + disabled 表达。本节保留仅为历史参考,新实现不要再引入 footer。

## 2. Floating HUD

### 2.1 整体规格(默认变体:Two-row pill)

| 项 | 值 |
|---|---|
| 宽 | auto,最小 168pt |
| 高 | auto(两行 pill 约 50–60pt) |
| 圆角 | 14pt |
| 材质 | `windowBackgroundColor` 0.55 实色层 + `.popover` material(`NSVisualEffectView`,`blendingMode: .behindWindow`),三层叠加 |
| 背景 | 实色压底 + `.popover` 毛玻璃 + 0.5pt hairline 描边(`Color.primary.opacity(0.12)`),见 设计风格 §12.3 |

### 2.2 内容结构(variant 1)

VStack,spacing 7pt。每行结构如下:

```
[●]  ████████░░░░░░░░░░  [42%]
[●]  ███████████████░░░  [78%]
 18pt    flex,4pt bar     38pt
```

| 元素 | 规格 |
|---|---|
| 左侧 logo tile | `ServiceTile` 18pt 圆角 5pt,服务色填充 + 内嵌 logo 12pt(`codex.svg` / `claude.svg` / `antigravity.svg` / `cursor.svg` / `commandcode.svg`),logo 加载失败时回退字母 |
| 中间 bar | 高 4pt,圆角 2pt,状态色填充 + `.quaternarySystemFill` 轨道,flex 1(最小宽 56pt) |
| 右侧百分比 | 13pt .semibold tabular kerning -0.3,状态色(见 设计风格 §4.3),固定宽 38pt 右对齐(按「100%」定宽,各行进度条等长;`∞` 同宽) |
| 行内 spacing | 8pt(tile / bar / 百分比 三段之间) |

进度 = `primaryLimit.window.remainingPercent / 100`。没有任何服务勾选悬浮窗时只显示一行 `No services · 未启用任何服务`(11pt secondary)。bar + 文字均按 设计风格 §4.3 三档状态色显示；Cursor Unlimited 空出 bar 位保持三段对齐，右侧只显示 `∞`，不使用 100% 代替，也不另加文字。

| 6 | Horizontal slim · 横向窄条 | 顶部 / 底部窄边贴边 |
| 7 | 5h + Week verbose · 详细模式 | 同时看 5h 和周 |
| 8 | No chrome · 无背景纯文字 | 极致简约,文字带阴影直接铺桌面 |

  - `Remaining / 剩余`:选中窗口的最新采样剩余整数百分比(明确写「剩余」,与上方周期卡的「已用」比例区分),无数据为 `--`;数值按剩余状态着色(`statusColor`),其余两项 secondary。
  - `Today / 今天`（5H）或 `Current cycle / 当前周期`（周）:当前展示区间所有真实变动事件 delta 之和,格式 `-11% / +88% / 0%`;跨窗重置造成的剩余大幅回升(Δ ≥ 20%)不计入,避免把「旧窗口归零」误算成消耗。
  - `Updated / 更新`:选中窗口最新成功采样时间,无采样为 `--`；不再错误使用最后一次变动时间。周视图恒带日期,5H 仅在采样不落在今天时带日期(今天尚未刷新成功的场景),避免纯 `HH:mm` 被读成今天。

账号分区自身不再携带窗口切换控件；全局 segmented（见 §3.5.0a）始终决定所有分区的窗口视角。

内容区顶部标注展示范围 `MM-dd HH:mm → MM-dd HH:mm`,10pt monospaced tertiary：5H 为当天 `00:00 → 次日 00:00`；周视图依次展示当前周期和上一周期，每段边界都由 `resetsAt` 推导。

#### 3.5.2 变动折线图

5H 显示一个「今天」区段；周视图在同一张图和同一张表中展示「当前周期」与「上一周期」两个区段。周期区段通过顶部范围行和折线断点区分；无数据时显示居中 `No data for this window · 该窗口暂无数据`。

- 图表固定高 200pt(见 §3.5.0a),Swift Charts;整体左侧内缩 12pt,Y 轴刻度不贴面板内容左缘。
- 两条竖向参考线:`Window reset · 窗口重置`(虚线,5H 取当前 5 小时窗口起点 = 下次重置 − 5 小时,且落在今天;周视图取当前周期起点)与 `Now · 现在`(实线);线色 `secondary.opacity(0.45)`,顶部 9.5pt tertiary 标签。X 轴域包含这两个时刻。
- X 轴:不固定为整段周期，按选中窗口内实际数据的首尾采样时间(并包含两条参考线)自适应，两端各留 4% 跨度的余量；只有一个点或零跨度时用固定余量兜底(5H 15 分钟、周视图 30 分钟)。5H 标签 `HH:mm`，周周期标签 `MM-dd HH:mm`，两者都按 `desiredCount: 5` 自动稀疏刻度。
- Y 轴:选中窗口剩余百分比,固定 `0...100`,刻度 `0 / 20 / 50 / 80 / 100`。当前周期和上一周期在同一张图中按额度窗口独立绘制，跨周期重置不连接成同一条曲线；窗口类型改变时也重置该系列曲线基准。
- 折线按额度窗口分段(`series = windowIndex`):5H 的一天横跨约 5 个 5H 窗口,窗口边界处断线,不把上一窗口的低点与新窗口的高点连成假回升斜线;点与表格仍保留全部数据。
- 线:账号服务识别色,2pt。
- 点:真实变动事件和当前周期最新成功采样。最新采样的 delta 为空，不把跨窗口重置伪造为消耗；颜色按剩余百分比走 `statusColor`，其中 normal(>50%)档在图表内比全局中性灰加深一档(浅 `#56565A` / 深 `#AEAEB4`)，保证浅色模式下可读，点尺寸 40pt。
- 网格线 `.secondary.opacity(0.18)`、轴标签 `.secondary`,不再用最浅的 quaternary / tertiary 档。
- 图上保留真实变动点；即使本次刷新与上次同值，也至少显示当前周期最新采样，确保刷新状态不滞留在上一周期。

#### 3.5.3 时间线表格

点击 `变动明细 · N 条`(N = 真实变动条数;chevron.right / chevron.down,11.5pt medium secondary)展开,位于折线图下方,展示选中窗口内所有周期的真实变动和最新采样，按时间倒序；周视图的当前周期与上一周期共用一张表。无数据窗口占固定 80pt 高度。

列:

| 列 | 宽度 | 内容 |
|---|---|---:|
| Time / 时间 | 82pt | 采样或变动时间;跨天时 `MM-dd HH:mm`,否则 `HH:mm` |
| Change / 变动值 | 82pt | 真实变动为 `after - before`，如 `-12%` / `+59%`；最新采样为 `—` |
| After / 变动后剩余 | 104pt | 该时刻的窗口剩余整数百分比 |
| Reset / 重置时间 | 96pt | 该次采样的窗口重置时间;跨天时带日期,未知为 `--` |

表头 10.5pt .semibold tertiary,行文本 11.5pt monospaced secondary。负变动红色,正变动绿色;变动后剩余按状态色显示。

- `Color.secondary.opacity(0.15)` 填充 + 0.5pt `Color.secondary.opacity(0.25)` 描边,无阴影
- 12.5pt .medium,手型光标

> SwiftUI 推荐:系统 `.buttonStyle(.borderedProminent)` 视觉上接近 PrimaryButton,可作为替代。

### 历史恢复提示补充

统计页警告按状态区分：无有效快照（文件保留、采集暂停、恢复有效备份后重启）、格式不兼容（使用兼容版本）、等待核对、核对拒绝（历史保留、采集暂停、恢复日志或解决读写故障后重试）、DSH 冻结（仅该来源暂停）。受限提示允许多行显示，不截断采集状态。无有效快照及格式不兼容时不提供误导的设置重算入口。

设置页重新计算完成后，受限核对失败必须显示行内反馈并保留脱敏诊断；周期向量不一致时提示「费用已更新；周期归属存在差异，完整性未确认」，不显示为全部成功。
