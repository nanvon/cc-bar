## 0. 路线:对齐 prototype,系统默认作为底座

cc-bar 是高频菜单栏入口,Popover 5 秒钟的扫视体验决定了产品观感。系统默认 + 数据列表只能做到"够用",做不到"一眼看到最关心的"。所以所有界面均对齐设计稿 [Prototype.html](历史参考/设计稿/Prototype.html) 落地,关键信息层做自绘组件,非关键交互一律用系统默认。

落地原则:

1. **能用系统的就用系统的**(material / Form / Picker / Switch / DatePicker / GroupBox 都不重绘),作为视觉底座。
2. **prototype 里承担信息层级的自绘组件全部做**:进度环、weekly 条、服务 tile、KPI 大字 + delta chip、堆叠柱图、双行 pill HUD。这些是"焦点 / 比例 / 趋势"的视觉载体,不是装饰。
3. **prototype 里纯装饰的细节按取舍表处理**(下表)。

| 自定义项 | 落地 | 备注 |
|---|---|---|
| 产品识别色(Codex 石墨灰 / Claude 桃橙 / Cursor 系统灰) | ✅ | 见 §4.2；Cursor Unlimited 与计量消耗见 §4.2.1 |
| 双语版式(英文主 + 中文次) | ✅ | 见 §5 |
| 状态色(4 档:>50% normal / 20~50% warning / <20% low / =0 empty) | ✅ | 见 §4.3 |
| Tabular 数字 | ✅ | 见 §3 |
| 进度条 / 服务 tile / KPI 大字 + delta chip | ✅ | 见 §11（进度环已废弃） |
| 堆叠柱图 / 甜甜圈 / 面积线 / 热力图 | ✅ | 用 Swift Charts;热力图可自绘 |
| Sidebar + Panel 卡片(Stats / Settings) | ✅ | 见 04 |
| Toggle / Dropdown | ✅ | 见 界面布局 §4.4（Slider 未使用） |
| SF Symbols 图标 | ✅ | 见 §9 |
| 顶部 1pt 高光线(模拟玻璃反光) | ❌ | 系统材质已有玻璃感,边际收益低 |
| 内描边(`inset 0 0 0 0.5`) | ⚠️ | 大窗口/HUD 不做;Panel / KPI 卡需要描出"卡片感"时叠 0.5pt(见 §7) |
| 三层精确阴影 | ⚠️ | 系统优先;HUD 不够再叠 fallback(见 §7) |
| 自定义动画曲线 `cubic-bezier(0.2, 0.9, 0.3, 1.15)` | ⚠️ | Popover 出现可用,其余系统默认(见 §8) |
| 8 种菜单栏 / 8 种 HUD 变体 | ⚠️ | 未采用:菜单栏 / HUD 均只有默认变体(见 §11.5 / 界面布局 §2.3) |
| App 图标正式素材(仓鼠 + 额度条) | ✅ | 见 §9 + Onboarding |

## 1. 整体气质

- **关键词**:克制、原生、半透明磨砂、连续曲率(squircle)、**强信息层级**(焦点突出、次级弱化)。
- **禁用**:Material Design / Bootstrap / Fluent 风格的自造按钮、彩色阴影、霓虹高光、emoji 状态指示。
- **遵循**:macOS 26 Tahoe HIG。所有交互控件(Switch / Picker / DatePicker / SegmentedControl)用系统原生外观,不重绘。

---

## 2. 材质

全部用系统给的,不自己叠玻璃效果。

| 场景 | material |
|---|---|
| 菜单栏弹出面板 | `.popover` |
| 桌面悬浮窗 HUD | `windowBackgroundColor` 0.55 实色层 + `.popover` material（三层叠加，见 §12.3） |
| 主窗口侧边栏 | `.sidebar` |
| 主窗口卡片 / 分组 | SwiftUI `.regularMaterial` |

SwiftUI 侧:`.background(.regularMaterial)` / `.thinMaterial`。
AppKit 侧:`NSVisualEffectView`,`blendingMode = .behindWindow`。

**HUD 实现注意**:`NSPanel` 默认 background 是 `.clear`。实际实现为解决 `.hudWindow` 在彩色桌面下前景对比不足的问题,`FloatingContentView` 用「实色压底 + `.popover` 毛玻璃 + 0.5pt hairline 描边」三层叠加(见 §12.3),而**不是**在 SwiftUI 里手画 `RoundedRectangle.fill(.regularMaterial)`;阴影交给 `NSPanel.hasShadow`,不手动叠。

## 3. 字体

- 全部 `-apple-system` / `.systemFont`,不指定字族(系统自动切 SF Pro Display / Text)。
- **所有数字** tabular:SwiftUI `.monospacedDigit()`,AppKit `NSFont.monospacedDigitSystemFont(...)`。

### 字号体系(基于 prototype)

| 角色 | 字号 / 字重 / 字间距 | 用途 |
|---|---|---|
| KPI 大数字 | 22pt / .semibold / kerning -0.5 / 默认 design | Stats KPI 卡（Popover 主要额度 32pt 另见 §11.5） |
| Title | 17pt / .bold / kerning -0.4 | 窗口标题(如 `Statistics · 用量统计`) |
| Headline | 13pt / .semibold / kerning -0.1 | 节标题、Popover 服务名 |
| Body | 13pt / .regular | 正文标签 |
| Callout | 12.5pt / .regular | 紧凑正文 |
| Caption | 11pt / .regular / secondary | 副标、说明 |
| Mono small | 10pt / .regular / .monospaced design | 时间戳、路径 |
| Eyebrow | 10.5pt / .semibold / kerning +0.4 / 大写 | 小标签(`CODEX` 等) |

> SwiftUI 实现:`.kerning(...)` 等价于 prototype 里的 `tracking`,SwiftUI 没有 tracking API。
> 默认行高交给系统,不指定 `lineSpacing`。

## 4. 颜色

### 4.1 基础语义色

| 用途 | Token |
|---|---|
| 主文本 | `.labelColor` / SwiftUI `.primary` |
| 次要文本 | `.secondaryLabelColor` / `.secondary` |
| 三级文本(中文副标 / caption 二级) | `.tertiaryLabelColor` |
| 分隔线 | `.separatorColor` |
| 浅色填充 | `.quaternarySystemFill` / `.secondarySystemFill` |
| Accent | `systemBlue`(系统自动) |

### 4.2 产品识别色

| 服务 | 浅色 | 深色 |
|---|---|---|
| Codex | `#6C6C70`(石墨灰) | `#98989D` |
| Claude Code | `#D97757`(桃橙) | `#E68A6E` |
| Antigravity | `#4285F4`(Google 蓝) | `#669DF6` |
| Cursor | 系统 `Color.gray`(语义灰,随外观自动切换) | 同左 |
| Command Code | `#18181B`(极夜黑，取 commandcode.ai 官网主色) | 同左(未做深色变体) |
| Pi | `#2F5F8A`(品牌蓝，取 pi.dev 官网主色) | `#5082B4` |
| OpenCode | `#0F766E`(品牌青，取 opencode.ai 官网主色) | `#2DD4BF` |

**用在哪**:服务色点 / 服务 tile / logo / 堆叠柱图块 / 图例等服务识别元素。额度数字、进度条、HUD 百分比等额度状态载体统一走 §4.3 状态色,**不要**再用服务识别色。**不要**用在大面积窗口背景。

**渲染顺序**:Codex 永远第一,Claude 第二,**Antigravity 第三**,Cursor 第四,Command Code 第五（Popover 订阅额度）,其后用量统计中的 Pi、OpenCode。

> 实现:在 `Resources/Assets.xcassets` 里定义 `CodexAccent` / `ClaudeAccent` / `AntigravityAccent` / `PiAccent` / `OpencodeAccent` Color Set,Xcode 自动生成对应 `Color`。
>
> Cursor 与 Command Code **没有**建 colorset：Cursor 直接用系统 `Color.gray`(见 `Main/DesignSystem.swift` 的 `QuotaApp.tintColor`),官方品牌无单一强识别色,系统灰能同时适配深浅外观;Command Code 用写死的 `#18181B`,深浅两套外观下取值相同。Antigravity 使用 `AntigravityAccent`（`#4285F4` / `#669DF6`，Google 蓝）作为识别色。
>
> ⚠️ 已知风险:Cursor 的系统灰与 Codex 石墨灰(`#6C6C70` / `#98989D`)明度接近,在统计页「按服务」面板、堆叠柱图和图例里两者会并排出现,仅靠色块不易区分。当前依赖 logo(`cursor.svg` / `codex.svg`)与文字标签做区分;若后续实测确认辨识度不足,再单独为 Cursor 引入 colorset,不要临时改 Codex 的既有识别色。

### 4.2.1 Cursor 额度与统计费用

Cursor 的额度模型与 Codex / Claude 的「按窗口百分比」不同,展示规则单列:

| 场景 | 规则 |
|---|---|
| `isUnlimited == true` | 值位显示 `∞`(Popover 左栏 / 悬浮窗右侧 / 菜单栏一致),标签固定 `UNLIMITED`;**不**渲染百分比、进度条或环形,也不再另起文字重复一遍「不限额度」。禁止用 100% 冒充不限额度——那会让状态色变绿,读成「额度充足」而不是「不计量」。 |
| 额度维度 | 主额度固定 `cursor-total`(标签 `TOTAL`);`cursor-auto` / `cursor-api` 作为缩小额度行显示 `AUTO` / `API`,**不**映射为 Weekly——它们是同一计费周期下的不同维度,不是时间窗口。 |
| 费用口径 | Cursor 无本地日志,费用取远端已成功拉取事件的 `chargedCents` 汇总；Popover 复用 Codex / Claude 已有的 today / this week 展示位与样式,不增加 Cursor 专属标签或 tooltip。 |
| 覆盖或字段缺口 | 已有任意远端快照时，Cursor 单服务、总花费、按模型、按提供商和每日 tooltip 都显示已知 `chargedCents` 合计；后台继续补拉覆盖缺口。`chargedCents` 缺失仍通过 `UsageTotals.costIncomplete` 按 OR 传播作诊断，但不再把金额替换为 `--`；仅完全没有远端快照时显示 `--`，也不显示 `Partial / 不完整` 文案。 |

> `costIncomplete` 与既有的 `hasUnpricedUsage` 是两个独立标记:后者仅作诊断,语义和展示行为保持不变。

### 4.3 状态色

额度状态色按剩余比例分 **4 档状态色**,全局唯一来源是 `statusColor(remainingPercent:tint:)`(`Main/DesignSystem.swift`),Popover / Floating / Stats KPI 全部走它。产品识别色只用于服务标识(tile / logo / 图表),**不参与额度状态着色**。

| 状态 | 颜色 |
|---|---|
| 剩余 > 50% | normal:石墨灰(浅 `#6C6C70` / 深 `#98989D`),统一中性灰、不随服务色 |
| 剩余 20% ~ 50% | warning:浅色 `#F6C343` / 深色 `#FFE27A` |
| 剩余 < 20% | low:浅色 `#FF7A2F` / 深色 `#FFA15F` |
| 剩余 = 0 / 超限 | empty:浅色 `#FF4D6D` / 深色 `#FF7A90` |
| live(刷新正常) | `systemGreen` 小点 |
| stale(数据过期) | `systemOrange` 小点 |
| offline(连续失败) | `systemRed` 小点 |
| 服务状态 none(statuspage 正常) | `systemGreen` 6pt 圆 |
| 服务状态 minor | `systemYellow` 6pt 圆 |
| 服务状态 major | `systemOrange` 6pt 圆 |
| 服务状态 critical | `systemRed` 6pt 圆 |
| 服务状态 maintenance | `systemBlue` 6pt 圆 |
| 服务状态 unknown / 未拉到 | 不渲染 |

**菜单栏例外**:菜单栏图标使用 `isTemplate = true` 模式,只能黑/白随菜单栏深浅自动反色。**状态色规则不作用于菜单栏文字本身**;低额度提示通过 Popover header 状态点、悬浮窗百分比颜色、未来的通知体现。

**额度加载失败提示**:Popover 主账号卡片、其他账号行的额度加载失败文案统一用 `Color.orange` + 前置 `exclamationmark.triangle.fill` 图标(与文字同色),区别于普通 loading/占位态的 `.secondary` 灰色,提高可感知度。

## 5. 语言切换

### 5.1 通用版式

- **单语显示**:同一时间只渲染中文或英文,不再并列双语。
- 由 `Settings → General → Language` 控制,三档:`Follow System` / `中文` / `English`。默认 `Follow System`,根据 `Locale.preferredLanguages.first` 是否以 `zh` 开头解析为 zh / en(兼容简繁)。
- 设计文案仍按"主英 + 中文"成对编写,运行时由 `tr(en, zh)` 选词;不直译,中文要短而地道。
- **所有可见文案**都要写双语对照(en + zh),用于翻译;不允许只有单一语言的硬编码。

### 5.2 典型组合

| 场景 | 形态 |
|---|---|
| 节标题 | `tr("Menu Bar", "菜单栏")` |
| 行内标签 + 副标 | `Codex` 主行 + 下一行 `tr("OpenAI", "OpenAI · Plus")` |
| 描述段落 | 一段,按 language 选英文段或中文段 |
| 按钮 | `tr("Open Statistics", "查看统计")` |
| 空状态 | `tr("Waiting for data", "等待数据")` |

### 5.3 实现

- `Core/L10n.swift` 提供 `AppLanguage` enum 与全局 `tr(_:_:)` 函数。
- 调用方在 SwiftUI view body / 函数体内统一写:
  ```swift
  Text(tr("Menu Bar", "菜单栏"))
  ```
- `SettingsStore.shared.appLanguage` 持久化用户选择;`resolvedLanguage` 计算属性把 `.system` 解析为 `.zh / .en`。
- `BilingualInline` / `BilingualStack` 已改造为按 language 单语渲染,外部 API 兼容。
- AppKit `NSMenu`(Commands API、NSAlert)在切换 language 后,通常需要重启应用才能完全刷新;SwiftUI 视图(Popover、HUD、主窗口、Settings、Onboarding)运行时即时刷新。

## 6. 圆角

绝大多数用系统默认(`NSPopover` / `NSPanel` / `Window` 自己就有正确的连续曲率圆角)。需要自绘时按下表:

|---|---|
| Window | 12pt(系统给) |

| 行内 pill / 小标签 | 6–8pt |
| Weekly 进度条 | 2.5pt(条高 5pt 的一半) |

## 7. 阴影

**优先靠系统**。`NSPopover` / `NSPanel(.floating)` / `Window` 自带阴影。

**HUD 例外**:阴影交给 `NSPanel.hasShadow`(按内容 alpha 自动取圆角形状);SwiftUI 层的 `.shadow` 会被 panel 边界裁掉并与系统阴影叠加,所以**不要**手动叠。HUD 边缘用 0.5pt hairline 描边勾出(见 §12.3)。

不再叠"内描边模拟高光"。

## 9. 图标

- **一律 SF Symbols**,不自造 SVG(服务 logo 例外:Codex / Claude / Cursor 用自带 SVG,见 `Resources/Logos/`)。
- **服务 logo SVG 规范**(`Resources/Logos/*.svg`):统一 `viewBox="0 0 100 100"` 正方画布,图形**等比缩放到高度 80(即 y 10~90)并水平居中**,`fill="white"`(渲染侧统一走 template / `renderingMode(.template)`,实际颜色由调用方决定)。
  - 原因:菜单栏 `MenuBarBadgeImage.drawIcon` 与 `ServiceTile` 都把 logo 画进**固定正方 rect**、不做 aspect-fit。若 SVG 是非正方 viewBox 会被横向拉伸变形,若图形铺满画布(零留白)则视觉体量比其他 logo 大一圈。
  - 引入新服务 logo 时,先按此规范把上游原始 SVG 的 transform **烘焙进 path 坐标**(保持单 path、无 `<g transform>`),再入库。
- 常用清单:`gauge.medium` / `arrow.clockwise` / `chart.bar.xaxis` / `gearshape` / `xmark.circle.fill` / `line.3.horizontal` / `ellipsis.circle` / `circle.fill`(状态点) / `square.and.arrow.up` / `power` / `exclamationmark.triangle.fill`(错误提示) / `checkmark.circle.fill` + `circle`(Onboarding 账号检测状态图标,纯展示、不可点击)。
- **菜单栏图标用 template 模式**(`isTemplate = true`),自动适配深浅菜单栏。
- **App 图标**:使用仓鼠趴在绿 / 黄 / 橙额度条上的暖色插画,1024 / 512 / 256 / 128 / 64 / 32 / 16 多档存放在 `Resources/Assets.xcassets/AppIcon.appiconset/`,Xcode 自动按需取用。

## 10. 间距

4pt 基线:**`{2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 28, 32}`**。

- 卡片内 padding:14pt(Popover 服务 block)/ 16pt(主窗口卡片)。
- 卡片间间距:10pt(Popover 服务之间)/ 12pt(主窗口卡片之间)。
- 节标题与正文间距:10–12pt。
- 行内元素间距:6 / 8pt。
- 图标与文字间距:6 / 8pt。

**禁止**出现表外奇数尺寸(7pt / 9pt / 11pt 等)作为间距。
**例外**:具体控件的固定宽度(如百分比右对齐 frame `width: 42`、5h/1w 标签 frame `width: 24`)不在此约束内。

### 12.3 需要手写的差异(浅深色不一致,系统语义色覆盖不到的)

**Panel / 卡片背景**(Stats / Settings / Onboarding 都用):

| 模式 | 背景 |
|---|---|
| 浅色 | 实心 `#FFFFFF`(不透明) |
| 深色 | `rgba(60,60,63,0.4)` 半透 |

SwiftUI 实现:
```swift
@Environment(\.colorScheme) private var colorScheme

var panelBg: AnyShapeStyle {
    colorScheme == .dark
        ? AnyShapeStyle(Color(white: 0.235, opacity: 0.4))
        : AnyShapeStyle(Color.white)
}
```
再加 0.5pt 内描边:
```swift
.overlay(
    RoundedRectangle(cornerRadius: 10, style: .continuous)
        .strokeBorder(
            colorScheme == .dark
                ? Color.white.opacity(0.06)
                : Color.black.opacity(0.06),
            lineWidth: 0.5
        )
)
```

> 这是 prototype 给"卡片感"的唯一手段(没有阴影)。不加描边深色卡片会"飘"在窗口里。

**HUD 背景**:

| 层 | 内容 |
|---|---|
| 实色压底 | `Color(nsColor: .windowBackgroundColor)` @ 0.55 opacity |
| 毛玻璃 | `.popover` material(`NSVisualEffectView`,blendingMode `.behindWindow`) |
| 描边 | 0.5pt hairline `Color.primary.opacity(0.12)` |

实现见 `Floating/FloatingContentView.swift`(三层叠加,解决 `.hudWindow` 在彩色桌面前景下对比不足的问题)。阴影交给 `NSPanel.hasShadow`,**不要**在 SwiftUI 里再叠 `.background(.regularMaterial)` 或 `.shadow`。

**Segmented control**:

容器底色两套(自绘时照抄):浅色 `rgba(0,0,0,0.06)`、深色 `rgba(255,255,255,0.08)`。prototype 时期的 active 段是白色 pill + 微阴影,当前实现**不再使用**(见下面第三条)。

默认**直接用系统 `Picker(.segmented)`**(如 Timeline 的 `5H | 本周` 窗口切换),会自动适配,不要自绘。

例外是 **Stats 顶栏的粒度 + 时间范围控件**:三个粒度段数不同(日 9 段、周 / 月各 6 段),而需求要求三者总宽一致、段等分、与粒度控件之间不留空隙。系统 `Picker(.segmented)` 的段宽只按各自文案自适应,SwiftUI 也没有暴露 `NSSegmentedControl.distribution`,既不会拉伸填满给定宽度,段之间也不会等宽,做不到这个效果,所以这两个控件改为自绘(`SegmentedBar`,见 `Main/StatsView.swift`)。自绘时:

- 容器 2pt padding、圆角 7pt,底色按上表(浅 `rgba(0,0,0,0.06)` / 深 `rgba(255,255,255,0.08)`)。
- 段高 22pt、左右 10pt padding、圆角 5pt;`stretch` 打开时各段 `maxWidth: .infinity` 等分容器宽度。撑宽度的骨架用 `uniformSegments`,每段按所有档位里最长的文案取宽,保证等分后没有一段窄于自己的自然宽。
- **选中段用 `Color.accentColor` 填充 + 白色文字**,跟随 macOS 当前的 segmented 外观和 `sidebarItem` 的选中态,不用上表里 prototype 时期的白色 pill。
- 段间 1pt `Color.primary.opacity(0.12)` 分隔线,只在自己和左邻都未选中时出现。
- 两个控件必须用同一个组件,不能一个系统一个自绘——圆角、底色和字号对不上会很明显。

**Stats 堆叠柱图颜色**:每段直接取该服务的 `UsageApp.tintColor`,也就是 §12.2 那张表里的 colorset,浅深色都按外观自动切换(Claude 深色同样切到 `#E68A6E`)。图表不另设一套硬编码值。

### 12.4 状态点 / 标签可读性

- HUD 在深色玻璃上,状态点直接放系统色即可;不需要额外描边。
- 浅色模式下,状态点周围的 `Connected · 已连接` 文字用 systemGreen,**不**用 .primary,以保持和点的一致性。
- KPI 卡的 delta `↑ 12.4%` 浅色用系统 red,深色也随系统 red 自动切换;`↓ 2.3%` 用系统 green。**不**用产品色。
